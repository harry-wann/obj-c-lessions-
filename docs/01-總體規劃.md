# 01 總體規劃

> Objective-C 速成教學網站（工作代號：**小帳本 / LittleBook**）
> 目標：1–2 週內讓已有 Swift / Kotlin / TypeScript / Java 基礎的開發者，能在工作上讀懂、修改、新增 Objective-C 程式碼，並與 Swift 混編。

---

## 1. 定位與範圍

| 項目 | 內容 |
|---|---|
| 對象 | 本人一位使用者，有 Swift / Kotlin / TS / Java 基礎，無 C / Objective-C 經驗 |
| 期程 | 16 天完整版（每天 2–3 小時）；12 天速成版（略過選讀與面試等級內容） |
| 產出 | 全程做完得到一支完整可跑的 iOS App「小帳本」（記帳） |
| 涵蓋 | Objective-C 語言、Foundation、UIKit 基礎、記憶體管理、執行期、GCD、網路、持久化、**效能與多執行緒進階（不掉幀、高併發、鎖）**、**舊專案實戰（MRC、Storyboard、CocoaPods）**、Swift 混編、測試與偵錯 |
| 不涵蓋 | macOS AppKit、Core Data 深入（只導讀）、Metal / Core Animation 進階、App 上架流程 |

## 2. 六個設計原則

1. **對照優先**：每個概念先對照你已會的語言（Swift / Kotlin / Java / TS 四欄分頁），再講 Objective-C 怎麼寫、哪裡不同、哪裡會被既有直覺害到。
2. **實務導向**：每章至少一則「⚠️ 實務陷阱」與一則「💥 崩潰現場」——貼出真實的 crash 訊息，教你怎麼從訊息反推原因。進入工作後最先遇到的不是語法，是別人留下的 crash。
3. **手機優先**：內容與「手機可完成」的練習在手機上一樣順手；需要 Mac 的練習明確標示，並可從手機「加入回 Mac 待辦」，批次處理。
4. **一條主線**：每章的練習都是「小帳本」App 的一塊，不出孤立的玩具題。做完第 10 模組，App 就完成。
5. **資料結構穿插**：堆疊、佇列、鏈結串列、雜湊表、樹各在最合適的章節登場。先用 Objective-C 自己寫一次（順便練記憶體管理），再換成 Foundation 的現成類別，並比較差異。
6. **用語專業**：以台灣業界慣用的專業術語為主（物件、類別、方法、屬性、協定、區塊、記憶體、指標、執行緒、佇列、字串、陣列、字典、委派、回呼），術語首次出現時標英文原文，全站附**台灣 / 中國大陸 / 日本 IT 界**三方術語對照表（見 06）。
7. **兩種工作都要能接**：既能維護純 Objective-C 舊專案（MRC、Storyboard、CocoaPods，模組 11），也能在混編專案裡用 Swift 寫新功能（模組 12）。
8. **效能有數字**：多執行緒保護、高併發、不掉幀不是「知道就好」，而是有驗收指標的實作（模組 10）。

## 3. 版本與環境假設

- Xcode 16 以上（以當下最新穩定版為準），部署目標（deployment target）iOS 17 以上。
- 全程 ARC、Modern Objective-C：字面值語法（`@[]`、`@{}`、`@()`）、屬性自動合成、輕量泛型、nullability 標注、`@import` 模組。
- UI **兩種都用**：列表與編輯頁用程式碼 Auto Layout，設定頁用 Storyboard（static cells + segue），交易 cell 另做 XIB 版本；模組 11 再用 Storyboard 重做一頁並處理合併衝突。
- Swift 對照以 Swift 5.x 語意為準；Kotlin 以 Kotlin 2.x、Java 以 Java 17、TypeScript 以 TS 5.x 為準。
- **重要**：Xcode Playground 不支援 Objective-C。練習中的「草稿本」一律改用「macOS Command Line Tool 專案（語言選 Objective-C）」或直接在 XCTest 測試裡寫。詳見 04。

## 6. 技術選型

### 建議：Astro + MDX + TypeScript

| 層面 | 選擇 | 理由 |
|---|---|---|
| 框架 | **Astro 5**（靜態輸出） | 內容用 Markdown / MDX 寫，日後自己增修最方便；預設零 JS，手機載入快 |
| 互動元件 | **Preact + TypeScript**（Astro islands） | 練習題元件用你熟的 TS 寫；只有練習區塊載入 JS |
| 樣式 | Tailwind CSS | 行動優先排版省工；深色模式一行搞定 |
| 程式碼高亮 | Shiki（內建 `objective-c` 語法） | 建置期高亮，手機不耗電；可同時高亮 Swift / Kotlin / Java / TS |
| 搜尋 | Pagefind | 純靜態全文搜尋，支援中文 |
| 離線 | `@vite-pwa/astro` | 通勤時離線閱讀已瀏覧章節 |
| 部署 | GitHub Pages + GitHub Actions | 推到 `main` 自動部署，零成本 |
| 內容格式 | 課文 `.mdx`；題目 `.yaml` | 題目與課文分離，便於批次增題與驗證 |

**不選 Next.js**：不需要 SSR，多一層複雜度。**備案 VitePress**：設定更少，但客製練習題 UI 較綁手，若想一週內先上線可考慮。

## 7. 手機版設計要點

這一節是整個網站的重點之一，獨立列出：

**排版**
- 單欄；底部導覽列四格（課程 / 練習 / 專案 / 速查）；章節目錄做成底部抽屜（bottom sheet），不佔版面。
- 觸控目標 ≥ 44pt；章節底部放大型「下一節」按鈕；頂部細條閱讀進度。
- 表格在窄螢幕自動轉成卡片；四語言對照用分段控制器（segmented control）切換，而不是四欄並排。
- 字型：Noto Sans TC（內文）＋ JetBrains Mono（程式碼）；中文與等寬字混排時行高固定，避免跳動。

**程式碼區塊**
- 預設不換行、可橫向捲動；提供「換行 / 不換行」、「字級 A− A＋」、「複製」三個按鈕，設定全站記住。
- 範例程式碼每行以 72 字為上限，手機不用捲也看得完整；長的方法呼叫刻意依 Objective-C 慣例按冒號對齊斷行，順便示範正確排版。
- 陷阱卡的「錯誤 / 正確」在手機改為上下排列，各自有紅 / 綠左邊框。

**練習輸入**
- iOS 鍵盤輸入 `[ ] { } * ^ @ ;` 很痛苦，練習題的輸入框上方固定一條 **Objective-C 符號快捷列**：`[ ] { } ( ) @ ; * ^ : - " _`。
- 手機以**點選類題型**為主（選擇、排序、點選錯誤行、填空用候選詞片），需要打一大段程式碼的題目標示「建議在 Mac 上做」。
- 每道 Xcode 任務在手機上有「加入回 Mac 待辦」按鈕；首頁顯示待辦數。

**離線與系統**
- PWA：讀過的章節自動快取；深色模式跟隨系統；支援 iOS 「加到主畫面」。

## 8. 進度與資料

- 進度（章節完成、練習結果、Xcode 任務勾選、錯題紀錄）存 `localStorage`。
- 提供**匯出 / 匯入 JSON**：手機 ⇄ Mac 同步用 AirDrop 或 iCloud Drive 即可，不需後端。
- 第三階段若有需要再加登入（GitHub OAuth ＋ Gist 存進度）。
