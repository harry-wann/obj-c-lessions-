## 模組 1 · C 語言地基 ⏱ 1 天

Objective-C 是 C 的嚴格超集，你缺的 C 知識只有這些：

| 章 | 主題 | 重點 |
|---|---|---|
| 1.1 | 基本型別與 Foundation 別名 | `int` / `long` / `double` / `char`；為什麼 Apple 要你用 `NSInteger` / `NSUInteger` / `CGFloat`（32 / 64 位元）；`BOOL` 與 `YES` / `NO`；`typedef` |
| 1.2 | 指標 | `*` 宣告與解參考、`&` 取址、為什麼**每個物件變數都是指標**（`NSString *s`）、`nil` / `NULL` / `Nil` / `NSNull` 四者差別、`NSNotFound`、傳址參數 `NSError **` 的由來 |
| 1.3 | struct 與 enum | `CGRect` / `CGPoint` / `CGSize` / `NSRange` 與 `CGRectMake`；`NS_ENUM` / `NS_OPTIONS` 的正確寫法與命名；位元旗標 `|` `&`；`switch` 配 enum 要不要 `default` |
| 1.4 | 函式、static、const、extern | C 函式 vs 方法；`static` 檔案私有；全域常數的標準寫法 `.h: extern NSString * const LBErrorDomain;` `.m: NSString * const LBErrorDomain = @"...";`；`const` 的位置意義 |
| 1.5 | 前置處理器 | `#define` 巨集與括號、`#pragma mark -` 分段、`#if DEBUG`、`#ifdef`、為何現代 ObjC 少用巨集改用 `static const` 與 inline 函式 |

🔁 對照：Swift 沒有指標（`inout` ≈ 傳址）、`Int` 自動 64 位元；Kotlin / Java 沒有無號整數（Kotlin 有 UInt 但少用）、沒有指標；TS 只有 `number`。四個語言都是 GC 或 ARC，從沒想過「這個變數是位址」——這是第一個心智模型轉換。
⚠️ 陷阱：整數除法 `7 / 2 == 3`；`BOOL` 存入非 0 / 1 的值造成 `if (flag == YES)` 失敗（永遠寫 `if (flag)`）；**`switch` 不能用在字串或物件上**（Kotlin `when` / Swift `switch` 的直覺會害你）；巨集沒加括號 `#define SQUARE(x) x*x`；用 `==` 比較字串。
💥 崩潰現場：`EXC_BAD_ACCESS (code=1, address=0x0)`——解參考空指標；`Thread 1: signal SIGABRT` 是什麼、怎麼看堆疊追蹤（stack trace）的第一個自己的 frame。
🌐：預測輸出（整數除法、位元旗標）、填空（`NS_ENUM` 宣告）、找錯（巨集括號）。
💻：在 `LittleBook` 建立 `LBTypes.h`：`LBTransactionKind`（`NS_ENUM`：支出 / 收入）、`LBTransactionFlags`（`NS_OPTIONS`：已對帳 / 定期 / 已刪除）；全域常數 `LBErrorDomain`；格式化金額的 C 函式 `LBFormatCents`。附測試。
📱：型別與常數定義就位。
🧱：位元旗標與位元運算複習。

## 模組 2 · 物件、類別與訊息傳遞 ⏱ 1.5 天

| 章 | 主題 | 重點 |
|---|---|---|
| 2.1 | 類別宣告與實作 | `@interface LBTransaction : NSObject` / `@end` / `@implementation`；實體變數（ivar）寫在 `{}` 或自動合成；`-` 實體方法、`+` 類別方法 |
| 2.2 | 方法與訊息傳遞 | 具名參數的方法簽名 `- (void)addAmount:(NSDecimalNumber *)amount note:(NSString *)note`；呼叫是「送訊息」`[ledger addAmount:a note:n]`；方法名其實是 `addAmount:note:`；巢狀呼叫的讀法；**對 nil 送訊息不會當掉**，回傳 0 / nil / NO |
| 2.3 | 建立物件與初始化器 | `[[LBTransaction alloc] init]`、兩段式建構；指定初始化器（designated initializer）與便利初始化器；`instancetype`；`if (self = [super init])` 的樣板；`NS_DESIGNATED_INITIALIZER`、`NS_UNAVAILABLE` 禁用 `init`；類別方法工廠 `+transactionWithAmount:` |
| 2.4 | 屬性 `@property` | attribute 全解：`nonatomic` / `atomic`、`strong` / `weak` / `copy` / `assign` / `unsafe_unretained`、`readonly` / `readwrite`、`getter=` / `setter=`、`nullable` / `nonnull`、`class`；自動合成 `_name`；點語法只是 getter / setter 的語法糖；何時直接用 `_ivar` |
| 2.5 | 封裝與「私有」 | ObjC 沒有 `private` 關鍵字：私有方法與屬性放在 `.m` 的類別延伸 `@interface LBLedger ()`；對外 `readonly` 對內 `readwrite` 的寫法；「私有」其實只是看不到，執行期仍可呼叫 |
| 2.6 | 繼承、覆寫與多型 | 單一繼承、`super`、覆寫要不要呼叫 `super`（看文件）、抽象類別的模擬、`isKindOfClass:` vs `isMemberOfClass:`、ObjC 沒有 `final`（可用 `__attribute__((objc_subclassing_restricted))`） |
| 2.7 | 相等、雜湊、描述與複製 | `==` 比位址、`isEqual:` 比內容、`isEqualToString:` 等特化版；覆寫 `isEqual:` 必須一起覆寫 `hash`（合約）；`description` / `debugDescription` 與 `po`；`NSCopying` 與 `copyWithZone:`；`NSMutableCopying` |
| 2.8 | 命名慣例與前綴 | 類別三字母前綴 `LB`（沒有命名空間）；方法像英文句子；getter 不加 `get`；布林屬性 `isEnabled` getter；分類方法加前綴 `lb_`；常數 `LBxxx`；Apple Coding Guidelines 摘要 |

🔁 對照：
- Swift：`init` 規則幾乎同源（designated / convenience），但 Swift 強制、ObjC 靠慣例；Swift `private` ↔ 類別延伸；`struct` 值型別在 ObjC 沒有對應物件版本（只有 C struct）。
- Kotlin：`data class` 一行幫你生 `equals` / `hashCode` / `toString` / `copy`——**ObjC 全部手寫**（2.7 整章就是在做這件事）；`object` 單例 ↔ `+sharedInstance` + `dispatch_once`；`companion object` ↔ 類別方法 `+`；主建構子 ↔ 指定初始化器。
- Java：`equals` / `hashCode` 合約一模一樣；`static` ↔ `+`；`instanceof` ↔ `isKindOfClass:`；`toString` ↔ `description`；`final` ↔ 無。
- TS：`class` 語法接近但 ObjC 把宣告與實作拆成兩檔；TS 結構型別（structural typing）vs ObjC 靠 `id` 與 `respondsToSelector:` 的鴨子型別（duck typing），其實 ObjC 比 Swift 更像 JS。

⚠️ 陷阱：
- 宣告忘記 `*`：`NSString s;` 編譯錯誤「interface type cannot be statically allocated」。
- `NSString` / `NSArray` / `NSDictionary` 屬性要用 `copy` 不用 `strong`：呼叫端傳入可變子類別後在外面改掉，你的屬性會跟著變。
- 在 `init` / `dealloc` 裡用 `self.prop` 還是 `_prop`：Apple 建議在這兩處直接用 ivar（避免觸發子類別覆寫的 setter 與 KVO）。
- `[super init]` 可能回傳 nil，所以要寫 `if (self = [super init])` 而不是 `self = [super init];` 後直接用。
- 用點語法呼叫無參數方法 `self.reload`：能編譯、能跑，但 code review 會被打回。
- `weak` 不能修飾基本型別與 struct，只能修飾物件指標。
- `nil` 訊息安全是雙面刃：少了 Kotlin 的 NPE / Swift 的 crash，錯誤會「無聲地」往後傳，debug 時要主動懷疑 nil。

💥 崩潰現場：`-[LBTransaction amout]: unrecognized selector sent to instance 0x600000c0` — 打錯方法名而編譯器只給 warning（因為 `id` 型別或 performSelector），怎麼從訊息讀出「哪個類別、哪個 selector、哪個實體」。

🌐：填空（屬性 attribute 選擇：給 5 個屬性選 copy / strong / weak / assign）、排序（`init` 樣板的正確順序）、找錯（`copy` vs `strong`、忘記 `*`）、預測輸出（對 nil 送訊息）、Parsons 題：拼出一個完整類別。
💻：實作 `LBTransaction`（不可變 model：id、金額 `NSDecimalNumber`、日期、備註、分類、種類）與 `LBCategory`（名稱、圖示、父分類），含指定初始化器、`isEqual:` / `hash` / `description` / `NSCopying`；通過 `LBTransactionTests`。
📱：資料模型完成。
🧱：參考語意 vs 值語意複習（為什麼 `copy` 等於「在邊界上把參考變成值」）。

## 模組 3 · Foundation 容器與字串 ⏱ 1 天

| 章 | 主題 | 重點 |
|---|---|---|
| 3.1 | NSString / NSMutableString | 字面值 `@"..."`、`stringWithFormat:`、`isEqualToString:`、`hasPrefix:` / `containsString:`、`componentsSeparatedByString:`、`substringWithRange:`、`length` 是 UTF-16 單位（emoji 算 2）、`NSNumberFormatter` / `NSDateFormatter`（金額與日期顯示）、`NSLocalizedString` |
| 3.2 | NSNumber / NSValue / NSDecimalNumber | 裝箱 `@42` `@(x)` `@YES`、拆箱 `integerValue`；`NSValue` 包 struct；**金額一律用 `NSDecimalNumber`**，`double` 會有 0.1 + 0.2 問題；`NSDecimalNumberHandler` 四捨五入 |
| 3.3 | NSArray / NSMutableArray | 字面值 `@[]`、`arr[0]`、`firstObject` 不會越界 vs `objectAtIndex:0` 會；快速列舉 `for (x in arr)`；`enumerateObjectsUsingBlock:`；排序 `sortedArrayUsingComparator:` / `NSSortDescriptor`；過濾 `filteredArrayUsingPredicate:`；`indexOfObject:` 用 `isEqual:`；`containsObject:` |
| 3.4 | NSDictionary / NSSet / NSOrderedSet / NSIndexSet | 字面值 `@{}`、`dict[@"k"]`、鍵必須遵循 `NSCopying`、取不存在的鍵回 nil 不會當；`enumerateKeysAndObjectsUsingBlock:`；`allKeys` 順序不保證；`NSSet` 的 `hash` 依賴；`NSCountedSet` |
| 3.5 | 可變 vs 不可變的設計哲學 | 預設不可變、需要才 `mutableCopy`；屬性對外宣告不可變型別、內部持有可變版本；`copy` 回傳不可變、`mutableCopy` 回傳可變；集合類別叢（class cluster）：`NSArray` 其實是 `__NSArrayI` |
| 3.6 | 輕量泛型與 nullability | `NSArray<LBTransaction *> *`、`NSDictionary<NSString *, NSNumber *> *`、`__kindof`；`NS_ASSUME_NONNULL_BEGIN / END`、`nullable` / `nonnull` / `null_resettable`；只是編譯期提示，執行期全部抹除；對 Swift 匯入成 `[LBTransaction]` 與 Optional 的影響 |
| 3.7 | KVC 與集合運算子（選讀） | `valueForKeyPath:@"@sum.amount"`、`@max` / `@distinctUnionOfObjects`；好用但效能與型別安全差，知道就好 |

🔁 對照：
- **Kotlin `List` / `MutableList` 與 `NSArray` / `NSMutableArray` 哲學幾乎相同**（唯讀介面 vs 可變實作）——這是你最大的優勢。
- Swift `Array` 是值型別，`let` 就不可變；ObjC 的 `NSArray` 是參考型別、不可變靠類別不靠關鍵字。
- Java `List` / `ArrayList` / `Collections.unmodifiableList`。
- TS `map` / `filter` / `reduce` 在 ObjC **沒有對應方法**：用 `enumerateObjectsUsingBlock:`、`NSPredicate`，或自己寫 `NSArray+LBFunctional` 分類（5.3 會做）。
- 字串：四個語言都有字串插值 ↔ ObjC 只有 `stringWithFormat:`，而且 `%@` 要對應物件、`%ld` 對 `NSInteger` 要轉型 `(long)`。

⚠️ 陷阱：
- 列舉中修改集合 → 直接 crash；要改就先 `copy` 一份或收集索引後再刪。
- 把 nil 放進 `@[]` / `@{}` → crash；要表示「沒有」用 `NSNull`，取出時要判斷。
- 回傳 `NSArray *` 但實際給出內部的 `NSMutableArray`，呼叫端 cast 後就能改你的內部狀態。
- 用 `==` 比 `NSString` / `NSNumber`：小整數與短字串因 tagged pointer 常常「剛好相等」，上線後才出事。
- `length` 與 emoji / 中文：`@"👍".length == 2`；要字元數用 `enumerateSubstringsInRange:options:NSStringEnumerationByComposedCharacterSequences`。
- 字典遍歷順序不保證，測試不能依賴。
- `NSInteger` 用 `%d` 印，在 64 位元是 warning，正確是 `%ld` + `(long)`。

💥 崩潰現場：
- `*** -[__NSArrayI objectAtIndex:]: index 3 beyond bounds [0 .. 2]`
- `*** -[__NSPlaceholderArray initWithObjects:count:]: attempt to insert nil object from objects[1]`
- `*** Collection <__NSArrayM: 0x…> was mutated while being enumerated.`
看類別名 `__NSArrayI`（不可變）/ `__NSArrayM`（可變）/ `__NSPlaceholderArray`（字面值建構中）就能推出事發位置。

🌐：預測輸出（tagged pointer `==`、`length` 與 emoji、字典順序）、填空（`stringWithFormat` 格式指定子）、找錯（列舉中刪除）、選擇題（哪些型別可以當字典鍵）、程式碼撰寫：寫一個 `sortedArrayUsingComparator:` 依日期倒序。

## 模組 4 · 記憶體管理與 ARC ⏱ 1 天

這是從 GC 語言（Kotlin / Java / TS）過來最大的心智模型轉換；Swift 經驗會幫你很多。

| 章 | 主題 | 重點 |
|---|---|---|
| 4.1 | 參考計數心智模型 | 擁有權（ownership）：誰 `alloc` / `retain` / `copy` 誰負責 `release`；`autorelease` 延後釋放；為了讀懂舊專案（MRC）要認得 `retain` / `release` / `autorelease` / `dealloc` 裡的 `[super dealloc]`，但新程式碼不寫 |
| 4.2 | ARC 的規則 | 編譯器在編譯期插入 retain / release；變數修飾 `__strong`（預設）/ `__weak` / `__unsafe_unretained` / `__autoreleasing`；屬性 attribute 對應；ARC 禁止的事（手動 retain、`NSAutoreleasePool` 物件、struct 內放物件指標） |
| 4.3 | 循環參考（retain cycle） | 父子物件、delegate（所以要 weak）、`NSTimer` 持有 target、block 捕獲 self、通知的 block API；用 Xcode **Memory Graph Debugger** 與 Instruments **Leaks** 找出來 |
| 4.4 | dealloc 與 autoreleasepool | `dealloc` 不呼叫 `[super dealloc]`（ARC）、裡面能做什麼不能做什麼；迴圈內大量暫存物件要用 `@autoreleasepool {}` 包；物件生命週期時序圖 |
| 4.5 | Core Foundation 橋接 | `CFStringRef` ↔ `NSString *`：`__bridge`（不轉移擁有權）、`__bridge_transfer` / `CFBridgingRelease`（CF → ObjC 並交給 ARC）、`__bridge_retained` / `CFBridgingRetain`；CF 的 Create / Get 命名規則 |

🔁 對照：
- Swift：ARC 幾乎相同；`weak` 同義；Swift `unowned` ≈ ObjC `__unsafe_unretained`（但 ObjC 幾乎不用，一律 weak）；`[weak self]` ↔ `__weak typeof(self) weakSelf = self;`。
- Kotlin / Java / TS：GC 幫你處理循環參考，ObjC **不會**——Activity 洩漏（Android）與 ObjC 的 retain cycle 是同一類問題，但 ObjC 更常見、更隱蔽。
- Java 的 `WeakReference` ↔ `__weak` 的精神相同，但 ObjC 的 weak 是語言級、歸零（zeroing）。

⚠️ 陷阱：
- 讀 weak 變數前先轉成 strong 區域變數（`__strong typeof(weakSelf) strongSelf = weakSelf; if (!strongSelf) return;`），否則多執行緒下可能中途變 nil。
- `dealloc` 裡不能再建立 weak 參考指向 self。
- `NSTimer scheduledTimerWithTimeInterval:target:` 強持有 target；不 `invalidate` 永不釋放；iOS 10 後用 block 版加 weakSelf。
- 「我用了 weak 所以沒問題」——weak 的 delegate 若在外面沒人持有會提早變 nil，功能悄悄失效。
- `NSNotificationCenter addObserverForName:...usingBlock:` 回傳的觀察者要自己 `removeObserver:`，selector 版 iOS 9 後不用。
- 在 `for` 迴圈建立數萬個暫存物件卻沒包 `@autoreleasepool`，記憶體峰值爆掉。

💥 崩潰現場：
- `EXC_BAD_ACCESS (code=1, …)` 存取已釋放物件 → 開 **Zombie Objects** 後變成 `-[LBTransaction amount]: message sent to deallocated instance 0x…`，一秒定位。
- Memory Graph 中看到紫色 ! 的洩漏物件、怎麼看持有鏈（retain chain）。

🌐：看圖點選（五張物件關係圖，點出有循環參考的那張）、填空（weakSelf / strongSelf 樣板）、選擇題（哪個屬性該 weak）、預測（weak 變數何時變 nil）。
💻：

## 模組 5 · 協定、委派、分類與區塊 ⏱ 1.5 天

| 章 | 主題 | 重點 |
|---|---|---|
| 5.1 | `@protocol` | `@required` / `@optional`、遵循 `<LBLedgerObserver>`、`id<LBLedgerObserver>` 型別、`respondsToSelector:` 檢查 optional、協定繼承 `<NSObject>`、`conformsToProtocol:` |

🔁 對照：
- Swift：protocol / extension / closure 一對一對應，差在語法；Swift protocol 可有預設實作（protocol extension），**ObjC 不行**，要改用基底類別或分類。
- Kotlin：`interface` ↔ 協定；**extension function ↔ 分類**（但 Kotlin 擴充是靜態派送，ObjC 分類是真的加進類別、執行期全域生效）；lambda ↔ block；尾隨 lambda 語法 ObjC 沒有；`fun interface` ↔ 單方法協定。
- Java：`interface` / 匿名內部類別 / lambda；`default` 方法 ↔ 無。
- TS：`interface` ↔ 協定（但 TS 是結構型別，ObjC 要明確宣告遵循）；箭頭函式 ↔ block；`Promise` ↔ completion handler（ObjC 沒有 Promise，callback 巢狀是日常）；JS 閉包捕獲是**參考**、ObjC block 捕獲是**值**——這是最容易被 JS 直覺害到的點。

⚠️ 陷阱：
- block 內用 `self` 又被 self 持有 → 循環參考；標準解法 weakSelf / strongSelf。
- block 屬性沒寫 `copy`（ARC 下其實會自動 copy，但慣例與可讀性仍要寫）。
- 呼叫 optional 協定方法前沒 `respondsToSelector:` → crash。
- 兩個分類加了同名方法，哪個生效看連結順序，無編譯錯誤 → 一律加前綴。
- 想在 block 裡改外部變數忘記 `__block`，編譯錯誤「variable is not assignable」。
- completion 在 early return 路徑忘記呼叫，或錯誤與成功路徑都呼叫（呼叫兩次）。
- `NSNotification` 的 `object` 與 `userInfo` 搞混；在 `viewWillAppear` 重複註冊觀察者。

💥 崩潰現場：
- block 為 nil 直接呼叫 `completion(YES, nil)` → `EXC_BAD_ACCESS`，正確 `if (completion) completion(YES, nil);`
- `-[LBSettingsViewController ledger:didRemoveTransaction:]: unrecognized selector` → optional 協定方法未檢查。

🌐：**block 語法填空**（這個題型要反覆練，列 10 題變化）、預測輸出（捕獲值 vs `__block`）、找循環參考、排序（委派流程）、程式碼撰寫：寫出 `typedef` 與一個接受 completion 的方法簽名。
💻：
1. `LBLedgerObserver` 協定（`ledger:didAddTransaction:` required、`ledgerDidReset:` optional）＋ `LBLedger.delegate`。
2. `NSDecimalNumber+LBFormatting` 分類（`lb_currencyString`）、`NSArray+LBFunctional`（`lb_map:` / `lb_filter:` / `lb_reduce:initial:`——補上 TS 直覺）。
3. `LBUndoStack`：以 block 封裝「復原動作」的堆疊，支援 `undo` / `redo`。
📱：帳本可觀察、可復原 / 重做；金額顯示格式化。

## 模組 7 · 錯誤處理、並行與網路 ⏱ 1 天

| 章 | 主題 | 重點 |
|---|---|---|
| 7.1 | `NSError` 慣例 | `- (BOOL)saveWithError:(NSError **)error;` 雙指標回傳錯誤、**先判回傳值再看 error**（Apple 文件明說）、`domain` / `code` / `userInfo`（`NSLocalizedDescriptionKey`、`NSUnderlyingErrorKey`）、自訂 `NS_ERROR_ENUM(LBErrorDomain, LBErrorCode)`、錯誤包裝與傳遞 |
| 7.2 | 例外與斷言 | `@try` / `@catch` / `@finally` / `@throw`、`NSException`；ObjC **不用例外做流程控制**（ARC 下例外不保證釋放、Foundation 丟的例外都是程式錯誤）；`NSAssert` / `NSParameterAssert` 只在 Debug 生效、`NSCAssert` 在 C 函式用 |
| 7.3 | GCD | 佇列（queue）概念：串列（serial）/ 並行（concurrent）；`dispatch_get_main_queue()`、`dispatch_get_global_queue(QOS_CLASS_USER_INITIATED, 0)`、自建 `dispatch_queue_create`；`dispatch_async` vs `dispatch_sync`；`dispatch_after`、`dispatch_once`（單例）、`dispatch_group`（等多個任務）、`dispatch_barrier_async`（讀寫鎖）、`dispatch_semaphore` |
| 7.4 | NSOperation / NSOperationQueue | 可取消、相依性 `addDependency:`、`maxConcurrentOperationCount`、`NSBlockOperation`、何時選它不選 GCD |
| 7.5 | 執行緒安全 | **`atomic` 不等於執行緒安全**（只保證單次存取完整）；可變集合不是執行緒安全；用串列佇列保護共享狀態（actor 的前身）；`@synchronized` 的代價；主執行緒才能碰 UI |
| 7.6 | `NSURLSession` | `sharedSession` vs 自訂 configuration、`dataTaskWithURL:completionHandler:` 要 `resume`、回呼在**背景執行緒**、HTTP 狀態碼要自己判、取消、ATS（App Transport Security）與 http 例外設定 |
| 7.7 | JSON 與資料映射 | `NSJSONSerialization` 回 `NSDictionary` / `NSArray`；**沒有 Codable**，手寫 `+[LBRate rateWithJSON:]`；型別防禦：`isKindOfClass:`、`NSNull`、數字當字串、缺欄位；日期字串 `ISO8601DateFormatter` |

🔁 對照：
- Swift：`throws` / `Result` / `async-await`；ObjC 的 `NSError **` 匯入 Swift 自動變 `throws`（12.1）；`DispatchQueue` 就是 GCD 的 Swift 包裝，一對一。
- **Kotlin coroutines**：`Dispatchers.Main` ↔ main queue、`withContext(Dispatchers.IO)` ↔ `dispatch_async(global)`、`launch` ↔ `dispatch_async`、`async / await` ↔ `dispatch_group` 或回呼；`suspend` 沒有對應，一切都是回呼。`Result` / sealed class 錯誤 ↔ `NSError`。
- Java：`ExecutorService` ↔ `NSOperationQueue`、checked exception ↔ `NSError`（都是「呼叫端必須處理」的哲學）、`synchronized` ↔ `@synchronized`。
- TS：`Promise` / `async-await` ↔ completion handler；`try / catch` 是流程一部分 ↔ ObjC 不是；單執行緒事件迴圈 ↔ 真多執行緒（要開始想 race condition）。

⚠️ 陷阱：
- 在背景執行緒更新 UI（`NSURLSession` 回呼預設就在背景）→ 要 `dispatch_async(main)`。
- 主執行緒上 `dispatch_sync(dispatch_get_main_queue(), …)` → 死結（deadlock），畫面卡死沒有錯誤訊息。
- 用 `if (error)` 判斷失敗：成功時 `error` 可能是垃圾值，要用回傳值。
- JSON 數字欄位用 `NSString` 接（或反過來）→ `unrecognized selector`。
- `dispatch_once` 的 token 宣告成區域變數（非 static）→ 失效。
- `atomic` 屬性當成執行緒安全在多執行緒 append `NSMutableArray` → 隨機 crash。
- `dataTask` 忘記 `resume`，什麼都沒發生也沒錯誤。

💥 崩潰現場：
- `Main Thread Checker: UI API called on a background thread: -[UILabel setText:]`
- `-[__NSCFNumber length]: unrecognized selector`（JSON 數字被當字串）、`-[NSNull length]: unrecognized selector`
- 死結：沒有訊息，怎麼在 Debug Navigator 暫停後看兩條執行緒互等。

🌐：預測輸出（`dispatch_async` / `sync` 執行順序，給 6 題）、找錯（UI 更新在背景、忘記 `resume`）、填空（`NSError **` 方法簽名與呼叫端）、JSON 防禦程式碼撰寫（給一段 JSON 與錯的解析碼，改寫成安全版）。
💻：
1. `LBRateService`：用 `NSURLSession` 抓匯率 JSON（提供一個免費端點與離線 stub 檔），解析成 `LBRate`，錯誤走 `NSError`，回呼切回主執行緒；測試用 stub 不打網路。
2. `LBSyncQueue`：模擬「離線待同步」的 FIFO 佇列，串列 dispatch queue 保護狀態，`dispatch_group` 等待全部完成。
3. 讓 `LBLedger` 的寫入在私有串列佇列上，讀取用 barrier——體會讀寫鎖。
📱：有匯率換算；帳本執行緒安全。
🧱：**佇列（Queue）**——FIFO、環狀佇列與陣列實作的取捨、生產者 / 消費者；（選讀）**堆積 / 優先佇列**排程「預算提醒」。

## 模組 10 · 效能、多執行緒進階與不掉幀 ⏱ 1.5 天

工作上「列表卡頓」「偶發 crash」「背景任務把 App 拖慢」是最常被指派的票。這一模組把模組 7 的並行基礎推到實務等級，驗收標準是數字：**捲動全程 ≥ 58 FPS、單幀主執行緒 < 8 ms、匯入 100,000 筆期間 UI 可操作、Thread Sanitizer 無警告**。

| 章 | 主題 | 重點 |
|---|---|---|
| 10.1 | 幀預算與主執行緒 | 60 / 120 Hz 的 16.7 / 8.3 ms 預算；主執行緒只做「算好的結果貼上去」；用 `CADisplayLink` 自己寫 FPS 監視器（環狀緩衝區取樣）；Instruments **Time Profiler** 與 **Animation Hitches** 的讀法；`os_signpost` 標記區間；Hitch 比率 |
| 10.2 | UITableView 不掉幀 | `cellForRowAtIndexPath:` 內**不准**建立 `NSDateFormatter` / `NSNumberFormatter`、不准算字串、不准同步 I/O；用 view model 預先把顯示字串算好（背景算）；列高預先計算快取 vs `estimatedRowHeight`；`prepareForReuse` 的最小重設；離屏渲染（`cornerRadius` + `masksToBounds`、沒設 `shadowPath` 的陰影、`mask`）；圖層混合（不透明背景）；`prefetchDataSource`；Debug → Color Blended Layers / Offscreen-Rendered |
| 10.3 | 大量資料匯入 | 100,000 筆 CSV：背景佇列串流解析、每 500 筆一批 `performBatchUpdates:`、進度回報**節流**（每 100 ms 一次，不是每筆一次）、`NSOperation` 可取消、迴圈內 `@autoreleasepool` 壓記憶體峰值、匯入中仍可新增交易（寫入序列化） |
| 10.4 | 鎖與同步原語 | `@synchronized`、`NSLock` / `NSRecursiveLock` / `NSCondition`、`os_unfair_lock`（不可遞迴）、`pthread_rwlock_t`、串列佇列 + `dispatch_barrier_async` 讀寫鎖、`dispatch_semaphore`；四種鎖的 benchmark（練習）；鎖的粒度；死結、優先權反轉（priority inversion）與 QoS；`atomic` 再談：為什麼它只保證「單次存取」 |
| 10.5 | 高併發設計 | 執行緒爆炸（thread explosion）：無限 `dispatch_async` 到並行佇列的後果；用 semaphore / `NSOperationQueue.maxConcurrentOperationCount` 限流；`dispatch_apply` 平行迴圈；`dispatch_group` 聚合；逾時與取消傳遞；**Thread Sanitizer** 開啟與讀報告；資料競爭（data race）vs 競態條件（race condition） |
| 10.6 | 搜尋與 debounce | 輸入 → 250 ms debounce → 背景過濾（可取消的 `NSOperation`，檢查 `isCancelled`）→ 主執行緒 diff 更新；舊結果晚到要丟棄（世代計數 generation counter）；對照 Kotlin `Flow.debounce` / TS lodash `debounce` |
| 10.7 | 記憶體與啟動時間 | `didReceiveMemoryWarning`、`NSCache` 自動清除 vs 自寫 LRU、Memory Graph 看持有鏈、Instruments **Allocations** / **Leaks**；啟動：`+load` 少做事、懶載入、`main` 前的 dyld 時間、App Launch Instrument |

🔁 對照：
- **Kotlin**：`Dispatchers.Main / IO / Default` ↔ 主佇列 / 全域佇列 QoS；`Mutex` ↔ `NSLock`；`Semaphore` ↔ `dispatch_semaphore`；`Flow.debounce` ↔ 自己寫；`withContext` 切回主執行緒 ↔ `dispatch_async(main)`；`RecyclerView` + `DiffUtil` 在背景算 diff ↔ 同一招。
- **Java**：`ReentrantReadWriteLock` ↔ `pthread_rwlock` / barrier；`ExecutorService` 固定大小執行緒池 ↔ 限流的 `NSOperationQueue`；`synchronized` ↔ `@synchronized`；`volatile` 沒有對應，請用佇列。
- **Swift**：`actor` 就是「串列佇列保護狀態」的語言級版本；`DispatchQueue` 一對一；`Task` 取消 ↔ `NSOperation` 取消。
- **TS**：單執行緒事件迴圈下你不用想鎖，這裡要；`requestAnimationFrame` ↔ `CADisplayLink`；Web Worker ↔ 背景佇列；`AbortController` ↔ `NSOperation.cancel`。

⚠️ 陷阱：
- 每個 cell 都 `new` 一個 `NSDateFormatter` → 捲動必掉幀（最經典）。
- `cornerRadius` + `masksToBounds` 套在每個 cell 的圖片上 → 離屏渲染；陰影沒 `shadowPath` → 每幀重算。
- 進度回報每筆 `dispatch_async(main)` 一次 → 主佇列塞爆，UI 比不回報還卡。
- 同一條串列佇列裡 `dispatch_sync` 回自己 → 死結。
- `os_unfair_lock` 遞迴加鎖 → 直接當。
- `@synchronized(self)` 鎖整個物件 → 粒度太大，所有方法互相等。
- 以為 `atomic` 保護了 `NSMutableArray` 的 `addObject:` → 隨機 crash。
- 高 QoS 任務等低 QoS 持有的鎖 → 優先權反轉，系統會偷偷升 QoS 但不一定來得及。
- 主執行緒做檔案 I/O 或 JSON 解析「只有幾 ms」→ 累積就是 hitch。

💥 崩潰現場：
- 主執行緒卡住 10 秒被系統殺：crash log `Exception Code: 0x8badf00d`（watchdog），怎麼從 log 找到卡住的堆疊。
- Thread Sanitizer 報告 `WARNING: ThreadSanitizer: data race ... Write of size 8 ... Previous read of size 8 ...` 的讀法：兩條堆疊各指向哪一行。
- `EXC_BAD_ACCESS` 在 `__NSArrayM insertObject:atIndex:` 多執行緒同時寫。
- Animation Hitches Instrument 裡紅色區段對到自己的 `cellForRowAtIndexPath:`。

🌐：預測輸出（佇列與鎖的執行順序 6 題）、找錯（cell 內建 formatter、進度每筆回報、sync 死結、unfair_lock 遞迴）、選擇題（哪種鎖適合哪種情境）、讀 TSan 報告選出競爭的兩行、排序（匯入流程的正確步驟）。
💻：
1. `LBFPSMonitor`（`CADisplayLink` + 環狀緩衝區）與**效能面板**頁（畫面 10）。
2. `LBImportService`：匯入 100,000 筆，分批更新、節流回報、可取消；驗收 UI 可操作。
3. `LBLedger` 改為串列佇列 + barrier 讀寫鎖；寫 `LBLockBenchmark` 比較 `@synchronized` / `NSLock` / `os_unfair_lock` / 串列佇列。
4. `LBSearchController`：debounce + 可取消背景過濾 + 世代計數（畫面 03）。
5. 交易列表 view model 化：cell 內零格式化；開 Color Offscreen-Rendered 確認全綠；Time Profiler 錄一段捲動。
6. 匯率 5 幣別並行抓取，semaphore 限流 2，`dispatch_group` 聚合（畫面 07）。
📱：效能面板、壓力測試、搜尋、匯入；列表捲 100,000 筆不掉幀。
🧱：**環狀緩衝區（ring buffer）**實作 FPS 歷史；**優先佇列**排程背景任務（選讀）；雜湊與陣列複雜度在搜尋情境的再確認。

## 附錄 C · 章節範例（用於校準用字與版型）

> 以下是 2.4「屬性 `@property`」的節錄草稿，用來確認用字風格與版型是否符合你的期待。全站所有章節會依這個密度與語氣撰寫。

### 2.4 屬性 `@property`

**學習目標**：看懂任何 `@property` 宣告的每個修飾詞；知道什麼時候用 `copy`；知道點語法在做什麼。⏱ 25 分鐘 · 前置：2.3

**你已經會的**

```swift
// Swift
class Transaction {
    var note: String          // 可讀可寫，值型別，拷貝語意
    let amount: Decimal       // 唯讀
    weak var delegate: TransactionDelegate?
}
```
```kotlin
// Kotlin
class Transaction(val amount: BigDecimal) {
    var note: String = ""
    // Kotlin 沒有 weak；靠 GC
}
```

**Objective-C 怎麼寫**

```objc
@interface LBTransaction : NSObject

@property (nonatomic, copy) NSString *note;
@property (nonatomic, strong, readonly) NSDecimalNumber *amount;
@property (nonatomic, weak, nullable) id<LBTransactionDelegate> delegate;
@property (nonatomic, assign, getter=isReconciled) BOOL reconciled;

@end
```

一個 `@property` 宣告，編譯器會幫你做三件事：產生一個實體變數 `_note`、一個 getter `- (NSString *)note`、一個 setter `- (void)setNote:(NSString *)note`。這叫**自動合成**（auto-synthesize）。括號裡的修飾詞決定這三樣東西怎麼產生：

| 修飾詞 | 意思 | 什麼時候用 |
|---|---|---|
| `nonatomic` | setter / getter 不加鎖 | **幾乎永遠**。`atomic` 是預設值但沒人想要（慢，又不是真的執行緒安全） |
| `strong` | 持有物件（ARC 預設） | 一般物件屬性 |
| `weak` | 不持有，物件釋放後自動變 nil | delegate、IBOutlet、避免循環參考 |
| `copy` | setter 存入的是 `[value copy]` | `NSString` / `NSArray` / `NSDictionary` / block |
| `assign` | 直接賦值，不管參考計數 | 基本型別（`BOOL`、`NSInteger`、`CGFloat`、struct） |
| `readonly` | 只產生 getter | 對外不可改的值 |
| `getter=isX` | 自訂 getter 名稱 | 布林屬性的慣例 |

點語法 `tx.note = @"午餐";` **完全等於** `[tx setNote:@"午餐"];`，`NSString *n = tx.note;` 等於 `[tx note]`。沒有魔法，只是語法糖。

**⚠️ 實務陷阱：`NSString` 為什麼要 `copy` 不要 `strong`**

```objc
// ✗ strong
@property (nonatomic, strong) NSString *note;

NSMutableString *draft = [NSMutableString stringWithString:@"午"];
tx.note = draft;          // 合法：NSMutableString 是 NSString 的子類別
[draft appendString:@"餐"];
NSLog(@"%@", tx.note);    // 印出「午餐」—— 你的屬性被外面改掉了
```
```objc
// ✓ copy
@property (nonatomic, copy) NSString *note;
// setter 存的是 [draft copy]，得到不可變的 NSString，外面怎麼改都不影響
```
Kotlin / Java 的 `String` 本來就不可變，你沒遇過這個問題；ObjC 的 `NSString` 有可變子類別，所以邊界上要用 `copy` 切斷。`NSArray` / `NSDictionary` 同理。

**💥 崩潰現場**

```
*** Terminating app due to uncaught exception 'NSInvalidArgumentException',
reason: '-[LBTransaction setAmount:]: unrecognized selector sent to instance 0x6000021c4a80'
```
`amount` 宣告成 `readonly`，所以沒有 setter。某處（通常是 KVC `setValue:forKey:` 或 Storyboard）試圖設定它。解法：在 `.m` 的類別延伸裡重新宣告為 `readwrite`（2.5 會教），或改用初始化器傳入。

**小測驗**（點選）
1. `@property (nonatomic) NSInteger count;` 的參考修飾詞是什麼？ → `assign`（基本型別的預設）
2. 哪個屬性應該用 `weak`？ (a) `NSString *title` (b) `id<UITableViewDelegate> delegate` (c) `NSArray *items` → (b)
3. `self.note = x;` 會呼叫哪個方法？ → `-setNote:`
