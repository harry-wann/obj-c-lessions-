# 03 實作專案：小帳本（LittleBook）

> 一支簡單但完整的記帳 App。每個模組的 Xcode 任務都是它的一塊，做完模組 12 就是成品，而且有兩個版本：**現代版**（ARC、程式碼 + Storyboard 並用、`NSURLSession`）與**老派版** `LittleBook-Legacy`（MRC、全 Storyboard、`NSURLConnection`、CocoaPods），後者是模組 11 的教材。
> 選記帳的理由：金額（`NSDecimalNumber`）、日期、分類階層、月結統計、復原、網路匯率、大量資料，剛好把課程要教的東西都用上，而且資料結構與效能議題出場得很自然。
> UI 設計稿：**https://www.figma.com/design/4d6HGy38x11n2uOfkzOBzj**（畫面編號與下表一致）。

## 2. 效能與多執行緒需求（驗收指標）

| 項目 | 指標 | 怎麼量 |
|---|---|---|
| 列表捲動 | 全程 ≥ 58 FPS，無離屏渲染 | 效能面板 FPS、Debug → Color Offscreen-Rendered |
| 單幀主執行緒 | < 8 ms（60 Hz 預算 16.7 ms 的一半） | `CADisplayLink` 量測、Time Profiler |
| 匯入 100,000 筆 | 期間 UI 可操作、記憶體峰值 < 150 MB、完成 < 20 s（模擬器） | 效能面板、Allocations |
| 搜尋 | 輸入到結果 < 100 ms（10 萬筆）、舊結果不覆蓋新結果 | 效能面板、單元測試世代計數 |
| 並行請求 | 50 個請求、限流 4，無執行緒爆炸（執行緒數 < 10） | 效能面板、Debug Navigator |
| 執行緒安全 | Thread Sanitizer 零警告；1,000 次並行讀寫帳本無 crash | TSan、`LBLedgerConcurrencyTests` |
| 鎖 | 四種鎖 benchmark 有數字並能解釋差異 | `LBLockBenchmark` |

## 3. 架構

簡單的 MVC ＋ 一層服務（service），刻意不引入 MVVM / 第三方庫（模組 11 才加 CocoaPods），因為工作上碰到的 ObjC 專案多數就是這個樣子。

```
Models/        LBTransaction  LBCategory  LBRate  LBMonthSection  LBTransactionViewModel（顯示字串預先算好）
Core/          LBLedger（帳本：資料與邏輯，串列佇列 + barrier 保護）  LBUndoStack  LBSettings
Services/      LBPersistence  LBRateService  LBSyncQueue  LBImportService  LBSearchController
Perf/          LBFPSMonitor  LBLockBenchmark  LBStressTests
Collections/   LBLinkedList  LBLRUCache  LBHashMap  LBRingBuffer  LBPriorityQueue（選）
Categories/    NSDecimalNumber+LBFormatting  NSArray+LBFunctional  NSDate+LBMonth
ViewControllers/
               LBTransactionListViewController        （程式碼）
               LBTransactionEditorViewController      （程式碼）
               LBCategoryPickerViewController         （程式碼）
               LBCurrencyPickerViewController         （程式碼，sheet）
               LBSettingsViewController               （Storyboard：Settings.storyboard）
               LBPerformanceViewController            （Storyboard segue 進入）
               StatsViewController.swift              ← 唯一的 Swift 檔
Views/         LBTransactionCell（程式碼）  LBTransactionCell.xib（XIB 版）  LBMonthHeaderView  LBBarChartView
Support/       LBTypes.h  LBConstants.h/.m  AppDelegate  SceneDelegate  main.m  Settings.storyboard
Tests/         每個 Core / Services / Collections / Perf 類別一個 XCTestCase
```

`LittleBook-Legacy/`：同樣的功能，但 MRC、全 Storyboard、`NSURLConnection`、`UIAlertView`、CocoaPods（AFNetworking + Masonry + SDWebImage），刻意埋 3 個 over-release、1 個洩漏、1 條斷掉的 IBOutlet、1 個缺 `-ObjC` 的 category crash。

## 4. 資料模型

```objc
// LBTransaction（不可變，NSCopying）
NSUUID *identifier
NSDecimalNumber *amount           // 永遠為正，方向由 kind 決定；原幣金額與匯率另存
NSString *currencyCode            // 預設 TWD
NSDecimalNumber *originalAmount, *exchangeRate   // 非主幣別時才有
LBTransactionKind kind            // NS_ENUM：Expense / Income
NSDate *date
NSString *note                    // copy
LBCategory *category
LBTransactionFlags flags          // NS_OPTIONS：Reconciled / Recurring

// LBCategory（樹節點）
NSString *identifier, *name, *symbolName; UIColor 由 colorKey 對應系統色
LBCategory *parent                // weak  ← 4.3 的教材
NSArray<LBCategory *> *children   // strong，對外不可變
- (NSUInteger)depth;  - (NSArray<LBCategory *> *)flattenedWithExpanded:(NSSet *)expandedIDs;

// LBLedger（可觀察、執行緒安全）
NSArray<LBTransaction *> *transactions           // readonly 快照，內部 NSMutableArray 依日期倒序
NSDecimalNumber *total                           // KVO-compliant，主執行緒通知
id<LBLedgerObserver> delegate                    // weak
- addTransaction: / removeTransactionWithIdentifier: / replaceTransaction:with:   // 寫：barrier
- transactionsGroupedByMonth → NSArray<LBMonthSection *>                           // 讀：並行
- transactionWithIdentifier:                     // 內部 NSDictionary 索引
- performBatchImport:(NSArray *)batch            // 匯入用，一次 barrier
```

## 5. 資料結構對應

| 需求 | 自己實作（練習） | 之後換成 | 章節 |
|---|---|---|---|
| 依 ID 快速找交易 | `LBHashMap` | `NSMutableDictionary` | 3.4 |
| 格式化字串快取 | `LBLinkedList` + `LBLRUCache` | `NSCache`（比較：會自動清） | 4.3–4.4 |
| 復原 / 重做 | `LBUndoStack`（雙堆疊，動作用 block 封裝） | `NSUndoManager`（比較） | 5.5 |
| 離線待同步 | `LBSyncQueue`（FIFO，串列佇列保護） | `NSOperationQueue` | 7.4 |
| FPS 歷史 | `LBRingBuffer` | — | 10.1 |
| 背景任務排程（選） | `LBPriorityQueue`（二元堆積） | `NSOperationQueue` 優先度 | 10.5 |
| 分類階層 | `LBCategory` 樹 ＋ 遞迴攤平 | — | 8.4 |
| 新交易插入位置 | 手寫二元搜尋 | `indexOfObject:inSortedRange:options:usingComparator:` | 8.4 |

## 7. 測試策略

- 核心邏輯（Models / Core / Services / Collections / Perf）**全部有單元測試**，UI 層做手動驗收清單。
- 並行測試：`LBLedgerConcurrencyTests` 用 `dispatch_apply` 同時 1,000 次讀寫；`XCTestExpectation` 驗證回呼在主執行緒。
- 效能測試：`XCTestCase measureBlock:` 量 `cellForRowAtIndexPath:` 平均時間與排序 10 萬筆。
- 網路以 stub 檔取代；持久化寫到 `NSTemporaryDirectory()`。
- 記憶體洩漏用「建立 → 弱參考 → 釋放 → `XCTAssertNil(weakRef)`」樣板。
