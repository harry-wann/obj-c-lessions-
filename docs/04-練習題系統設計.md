# 04 練習題系統設計

> 兩大類：🌐 **網頁驗證**（當場給結果）與 💻 **Xcode 任務**（在 Mac 上以 XCTest 驗證）。
> 核心限制：瀏覽器無法真正編譯 Objective-C，所以網頁題型要設計成「不需要編譯器也能嚴格判對錯」。

---

## 1. 題型總覽

| 代號 | 題型 | 手機友善 | 驗證方式 | 適合考什麼 |
|---|---|---|---|---|
| `quiz` | 選擇題（單選 / 多選） | ★★★ | 答案比對 | 概念、慣例、該用哪個修飾詞 |
| `fill` | 填空（候選詞片 / 短字串） | ★★★ | 正規化後比對、容許多解 | 修飾詞、格式指定子、關鍵字、block 語法 |
| `parsons` | 程式碼排序（拖曳或點選排序） | ★★☆ | 順序比對（容許等價順序） | `init` 樣板、生命週期、訊息派送流程 |
| `predict` | 預測輸出 | ★★★ | 字串比對（候選或輸入） | 整數除法、nil 訊息、block 捕獲、GCD 順序、tagged pointer |
| `spot` | 找錯（點選有問題的行，再從選項選原因） | ★★★ | 行號 ＋ 原因比對 | 循環參考、copy/strong、列舉中修改、UI 在背景執行緒 |
| `crash` | 讀崩潰訊息（給 log 選原因與修法） | ★★★ | 選項比對 | 工作上最常見的 crash |
| `code` | 短程式碼撰寫（5–15 行） | ★☆☆ | 網頁端靜態驗證器（見 §4） | 方法簽名、typedef、分類宣告、約束程式碼 |
| `xcode` | Xcode 任務 | — | XCTest 全綠 ＋ 勾選 | 實作 App 的每一塊 |
| `flash` | 速記卡（面試題） | ★★★ | 自評（會 / 不會） | 10.7 面試題、術語 |

每章配置建議：小測驗 3–5 題 `quiz` / `fill`；練習 2–4 題混合 `predict` / `spot` / `parsons` / `crash`；1 題 `code`（標示建議在 Mac 做）；1 題 `xcode`。

## 2. 手機友善原則

1. **點選優先**：手機上能做的題全部設計成不打字或只打一兩個字。
2. **候選詞片**：填空題在手機上顯示候選詞片（例如 `strong` `weak` `copy` `assign`），點一下填入；在桌面也可直接打字。
3. **符號快捷列**：所有輸入框上方固定 `[ ] { } ( ) @ ; * ^ : - " _` 一列，點了插入到游標處。
4. **分段作答**：`code` 題在手機可拆成「先選簽名 → 再選內容」兩段，桌面才要求整段輸入。
5. **回 Mac 待辦**：每道 `xcode` 題有「加入待辦」，首頁顯示待辦數；在 Mac 上打開網站時首頁第一格就是待辦清單。
6. **即時回饋但不洩題**：答錯顯示針對該錯誤的提示（提示階梯，見 §5），不直接給答案；第三次才可展開參考解答。

## 3. 題目定義格式（YAML）

題目與課文分離，放 `site/src/content/exercises/mXX/`。一題一檔或一章一檔皆可。

  @property (nonatomic, ___4___) NSInteger sortOrder;
  @property (nonatomic, ___5___) void (^onChange)(void);

blanks:

  4: { accept: [assign], chips: [strong, weak, copy, assign] }

hints:

## 4. 網頁端驗證器（`code` 題）

沒有編譯器，但可以做到「比正規表達式嚴謹、比編譯器寬鬆」的檢查。驗證器用 TypeScript 寫，分三層：

1. **正規化**：移除註解、折疊空白、統一引號；可選擇忽略變數名稱（以 `$1` 佔位）。
2. **輕量分詞與結構檢查**：中括號 / 大括號 / 小括號配對；`@interface … @end` 成對；方法簽名解析成 `{ scope: '-'|'+', returnType, selectorParts[], paramTypes[] }` 再比對。
3. **規則集**（每題在 YAML 宣告）：
   - `must_match`: 必須出現的結構（以解析後的簽名或正規表達式表示）
   - `must_not_match`: 禁止出現（例如 `strong` 修飾 `NSString`、`self` 直接出現在 block 內）
   - `selector_equals`: 方法名必須等於 `addTransaction:completion:`
   - `property_attrs`: 指定屬性必須含某些修飾詞

```yaml
type: code
checks:
  - selector_equals: "fetchRatesForBase:completion:"
  - must_match: 'typedef\s+void\s*\(\^\s*LBRateCompletion\s*\)\s*\(\s*NSDictionary\s*<\s*NSString\s*\*\s*,\s*NSDecimalNumber\s*\*\s*>\s*\*\s*_Nullable\s+\w+\s*,\s*NSError\s*\*\s*_Nullable\s+\w+\s*\)'
  - must_not_match: '\bself\b(?![^\^]*\^)'   # block 內不可直接用 self
  - brackets_balanced: true
```

**明講限制**：驗證器抓不到型別錯誤、找不到的 selector、記憶體問題。因此每道 `code` 題都附「貼進 Scratch 專案編譯」的按鈕提示，且答案通過後會顯示參考解答與逐行說明，讓你自己對照。

## 5. 提示階梯與回饋

- 第一次答錯：顯示通用提示 1（方向）。
- 第二次：提示 2（更具體）＋ 若命中 `feedback` 表中的特定錯誤答案，顯示針對性說明（這一步最有教學價值，例如「你選了 strong，這會造成…」）。
- 第三次：可展開參考解答與說明；題目標記為「答錯過」，加入複習池。
- 每天開站首頁出 5 題「複習池」的題目（簡單間隔重複：答對一次 2 天後再出，答對兩次 5 天後，三次移出）。

## 6. Xcode 任務的驗證

Xcode Playground 不支援 Objective-C，而 iPhone 上的 Swift Playgrounds 也不行，所以 Xcode 任務**只能在 Mac 上做**。驗證設計：

1. 每個里程碑的 starter 專案內含**已寫好、目前會失敗**的測試；任務卡列出要變綠的測試名稱。
2. 完成後在網站上勾選；若想要嚴格一點，可貼上 `xcodebuild test` 最後一行摘要（`Executed 12 tests, with 0 failures`）做簡單比對，但這只是自我約束，不是防作弊。
3. UI 類任務附「手動驗收清單」，一項一勾。
4. 「草稿本」用途一律指向 `xcode/Scratch`（macOS Command Line Tool，語言 Objective-C）：所有課文範例都能貼進 `main.m` 直接跑。

## 7. 線上編譯（Phase 3，選）

若之後想讓 Foundation 層的 `code` 題真的編譯執行：
- **Judge0**（開源線上評測）支援 Objective-C（clang ＋ GNUstep），可自架 Docker；或用其雲端 API（有免費額度）。
- 限制：GNUstep 的 Foundation 與 Apple 的有差異（部分新 API 沒有、`NSLog` 格式略不同）、**沒有 UIKit**、tagged pointer 行為不同。只適合 M1–M5、M7 的純邏輯題。
- 因此定位為「加分」而非核心，核心仍是 §4 的靜態驗證 ＋ Mac 上的 XCTest。

匯出為 JSON 檔、匯入時合併（以較新的 `lastAt` 為準）。
