## A. 必須先知道的現實限制

### A1. 瀏覽器無法真正編譯 Objective-C
網頁上做不到「寫一段 ObjC 按下執行」。對策已寫在 04：題型設計成不需要編譯器也能嚴格判對錯（選擇、填空、排序、預測輸出、找錯、讀 crash log），短程式碼題用靜態驗證器。真正要編譯的練習全部放到 Xcode。Phase 3 可選接 Judge0（GNUstep），但那只覆蓋 Foundation 層。
**建議**：接受此限制，不花時間做線上編譯；把網頁題做到精。

### A2. Xcode Playground 不支援 Objective-C，手機也沒有任何 ObjC 執行環境
你第 9 點寫「Xcode / playground」。Playground 只能跑 Swift；iPhone / iPad 上的 Swift Playgrounds 同樣不行。
**建議**：以 macOS「Command Line Tool（Objective-C）」專案 `xcode/Scratch` 當草稿本，所有範例都能貼進 `main.m` 跑；需要跑程式的練習全部是「回 Mac 待辦」。網站上的 Xcode 任務卡要有「加入待辦」，讓你手機讀完、坐到 Mac 一次做完。

### A3. 進度跨裝置同步
靜態網站沒有後端，手機與 Mac 的進度是兩份 `localStorage`。
**建議**：先做匯出 / 匯入 JSON（AirDrop 一下就同步），夠用；Phase 3 再評估 GitHub 登入。

## C. 我額外補進去的東西（你沒提但我認為必要）

1. **💥 崩潰現場**：每章一則真實 crash 訊息的解讀。進入工作後第一件事通常是看別人的 crash，而不是寫新語法。另外在速查區做一張「崩潰訊息排查表」（訊息 → 常見原因 → 修法）。
2. **讀懂舊專案（10.5）**：MRC 寫法、`@synthesize`、`NSURLConnection`、CocoaPods 專案結構、常見第三方庫。工作上 ObjC 專案幾乎都是「舊」的，看得懂比寫得出更急。
3. **偵錯工具（10.4）**：Exception Breakpoint、Zombie Objects、Memory Graph、Address / Thread Sanitizer、Analyze、符號化 crash log。這些比語法更能決定你第一週的生產力。
4. **訊息派送與 runtime（M6）**：你沒提，但它是 iOS 面試必考、也是理解 `unrecognized selector` 等一半以上 crash 的鑰匙。
5. **Swift ↔ ObjC 邊界資訊丟失（10.1、10.2）**：nullability 沒標 → Swift 端全是 `!`；Swift struct / enum 關聯值 ObjC 看不到。混編專案最常見的 bug 來源。
6. **金額用 `NSDecimalNumber`**：順便教「為什麼不能用 double 算錢」，這是記帳 App 的真實需求也是面試題。
7. **間隔複習**：首頁每天 5 題錯題池複習，不然 14 天後第 2 天的東西已經忘了。
8. **符號快捷列**：手機鍵盤打 `[]^@` 很痛苦，練習輸入框上固定一列符號。這是真正會影響你「用手機學」體驗的小細節。
9. **寫作規範（06 末段）**：避免機翻腔的具體規則，確保第 1 點需求落實到每一章。
10. **四語言對照總表（02 附錄 B）**：放進速查區，一張表看完所有對應關係。
11. **工作場景的 20 題面試 / 上工題（10.7）**：每題三行答案，當速記卡。
12. **程式碼風格與 clang-format**：進團隊第一天就會碰到 code review，提前知道慣例。

## D. 我刻意不做的事（避免範圍膨脹）

- 不做帳號系統、不做留言 / 社群功能（只有你一人使用）。
- 不做 UI 自動化測試（對學 ObjC 幫助小、維護成本高）。
- 不深入 Core Data、Core Animation、Metal、推播、上架流程（各自可成獨立課程）。
- 不教 Objective-C++（`.mm`）細節，只在 0.4 提一句。
- 不做 iPad 專屬排版。
