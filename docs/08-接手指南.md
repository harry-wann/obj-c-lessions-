## 2. 本機第一次要做的事（依序）

1. `git checkout claude/bold-planck-yrmdlc`（若已合併到 `main` 則用 `main`）。
2. 網站：`cd site && npm install && npm run build`，確認建置成功；`npm run dev` 用手機（同網段）開來看。
3. 安裝 XcodeGen：`brew install xcodegen`。
4. **Xcode 驗證（最重要）**：對每個 `xcode/M0X-solution` 跑 `xcodegen generate` 與 `xcodebuild test`，solution 必須全綠；starter 應該可以建置、測試為紅燈（M11、M12 的 starter 測試也是紅燈）。有錯就改 `xcode/src/` 再 `bash xcode/scripts/assemble.sh`，不要改組裝出來的資料夾。
5. Legacy：`cd xcode/LittleBook-Legacy && xcodegen generate`（可選 `pod install`），確認 6 個雷照 README 描述的症狀出現；`LittleBook-Legacy-solution` 則能正常執行。
6. 合併到 `main`，repo Settings → Pages → Source 選「GitHub Actions」。

## 3. 已知風險清單（Mac 驗證時優先看）

**XcodeGen / 專案設定**
- `project.yml` 的 `info.properties`（`UIApplicationSceneManifest` 巢狀結構、`UILaunchScreen: {}`）、`scheme.testTargets`、測試 target 的 `HEADER_SEARCH_PATHS`。
- 資源（`.storyboard`、`.xib`、`LegacyAudit.plist`）依副檔名自動進 Copy Bundle Resources，未逐一列出。
- 未設 `DEVELOPMENT_TEAM`；模擬器通常不需要。

**測試穩定性**
- M08：UIKit 測試依賴 window 掛到 scene、`layoutIfNeeded` 後 `performBatchUpdates` 的時機。
- M10：有時間假設的非同步測試——`LBSearchControllerTests`（0.1 / 0.5 秒）、`testConcurrentFetchLimitedBySemaphore`（stub 從 GCD 執行緒回呼、要求 > 0.3 秒）、`testCancelStopsImport`（假設 2 萬筆尚未解析完就取消）。
- M09：`NSSecureCoding` 巢狀解碼 `decodeObjectOfClass:` 的類別白名單。
- M04 之後：`__weak` 在 `@autoreleasepool` 後歸零的斷言。
- 效能面板的並行請求會打真網路 `api.frankfurter.app`，假設回應格式 `{"base":…,"rates":{…}}`。

**M11 / M12**
- Storyboard、XIB 是手寫的 Interface Builder XML，未經 ibtool。
- M12 的 Swift 從未編譯。最可能出錯：Notification 名稱匯入（`.LBLedgerDidImportBatch`、`.LBSettingsDidChange`）、`LBTransaction.Kind`（`NS_SWIFT_NAME` 巢狀名稱）、`ledger.add(_:)`、`fetchRates(forBase:)` 的 async 版、`LBStubURLProtocol.stubPath(_:statusCode:data:)`、`@testable import` 與測試橋接標頭並用、ObjC 測試找 `LittleBook-Swift.h` 的路徑（`$(CONFIGURATION_TEMP_DIR)/LittleBook.build/DerivedSources`）。
- `testNullabilityAnnotationsPresent` 用 `__FILE__` 讀原始碼，只在模擬器可行，實機會 `XCTSkip`。
- `-Werror` 只在 project.yml 留註解未開啟；驗證後可打開。
- `.clang-format` 未套用到程式碼（約 1,200 處不合格，留給學生做 12.5 練習）。

**LittleBook-Legacy**
- XcodeGen `library.static` 的 `headerVisibility: project`、`Base.lproj`。
- Podfile `post_install` 用到的 `xcconfig_path` API（刻意移除 Pods 帶的 `-ObjC`，讓雷 5 可重現）。
- 新版連結器（ld-prime）是否仍會丟掉只含 category 的 `.o`（雷 5 的前提）。

**內容需在 Mac 上核對的細節**
- 少數錯誤訊息字句是憑記憶撰寫：ARC 下 `NSLog("…")` 的轉型錯誤、`substringWithRange:` 越界格式、`Cannot form weak reference…`、`Terminated due to memory issue`、`objc_subclassing_restricted` 的編譯錯誤、`Class X is implemented in both`。
- 依實作細節的預期輸出：tagged pointer 的 `==`（3.1、3.2）、類別叢集名稱 `__NSArray0` / `__NSSingleObjectArrayI`（0.1、3.5）、`[^{…} class]` 印 `__NSStackBlock__`（5.5）、`NSNumberFormatter` zh_TW 貨幣符號（3.1）、`3-3-advanced-1` 擴容次數為估算值。
- 課文與專案的小差異：11.5 課文的 Podfile 寫 `platform :ios, '13.0'`，M11 專案用 `'17.0'`；11.6 的 `-force_load` 路徑寫 `$(SRCROOT)/Vendor/…`，Legacy 專案實際是 `$(BUILT_PRODUCTS_DIR)/libLBLegacyKit.a`。

