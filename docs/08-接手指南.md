## 2. 本機第一次要做的事（依序）

1. `git checkout claude/bold-planck-yrmdlc`（若已合併到 `main` 則用 `main`）。
2. 網站：`cd site && npm install && npm run build`，確認建置成功；`npm run dev` 用手機（同網段）開來看。
3. 安裝 XcodeGen：`brew install xcodegen`。
4. **Xcode 驗證（最重要）**：對每個 `xcode/M0X-solution` 跑 `xcodegen generate` 與 `xcodebuild test`，solution 必須全綠；starter 應該可以建置、測試為紅燈（M11、M12 的 starter 測試也是紅燈）。有錯就改 `xcode/src/` 再 `bash xcode/scripts/assemble.sh`，不要改組裝出來的資料夾。
5. Legacy：`cd xcode/LittleBook-Legacy && xcodegen generate`（可選 `pod install`），確認 6 個雷照 README 描述的症狀出現；`LittleBook-Legacy-solution` 則能正常執行。
6. 已完成：`main` 推送後自動部署（Pages Source＝GitHub Actions）。之後在 `claude/…` 分支開發，合併或快轉到 `main` 就會上線。

## 3. 已知風險與驗證紀錄

原本列的 XcodeGen 設定、Storyboard / XIB 手寫 XML、M08–M10 的時間敏感測試、`NSSecureCoding` 白名單、`__weak` 歸零斷言、Legacy 的 `headerVisibility` / `Base.lproj` / Podfile `post_install` / ld-prime 等項目，2026-11-16 在 Mac 上全部驗證通過，已從清單移除。

**驗證時發現並已修正**
- M12：`LBLedger` 有 `transactions` 屬性，Swift 不會把 `addTransaction:` 縮成 `add(_:)`，實際是 `addTransaction(_:)`（類別有同字根的屬性時 Swift 保留那個字）。測試與 11.1、12.1、12.3、12.5 課文已改，12.1 補上規則說明。
- M12：`@testable import` 一個有橋接標頭的模組時，靠模組帶進橋接標頭的行為在新版 Swift 已棄用（警告）。測試橋接標頭改為明確 `#import "LittleBook-Bridging-Header.h"`。
- Legacy 雷 5：XcodeGen 的 `requiresObjCLinking`（靜態庫預設 true）會自動替 App 加 `-ObjC`，雷 5 根本不會出現。埋雷版在 `LBLegacyKit` 設 `requiresObjCLinking: false`；實際接收者是 `__NSCFConstantString`，README、11.6 課文、11-6-crash-1 與 docs/02 已改。
- 11-6-xcode-1 的步驟與 Legacy 專案不符（雷 3 的 key、雷 4 改錯邊、雷 6 的 VC），已對齊。
- 內容實測後修正：`NSLog("…")` 的錯誤字句（0.3）、`substringWithRange:` 越界是 `NSInvalidArgumentException`（3.1）、iOS 14 / macOS 11 以上的常數字面值變成 `NSConstantArray` / `NSConstantIntegerNumber`，類別名與 `==` 結果跟著改變（2.6、3.2、3.5、6.1、6.3，以及 2-6-advanced-1、3-2-predict-3、3-5-predict-1、3-6-predict-1）、tagged pointer 位址已混淆（3.2）、iOS 26 的 `__NSArrayI` 越界訊息是 `__boundsFail`、下標是 `objectAtIndexedSubscript:`（3.3）、`appendString:` 對不可變字串丟 `Attempt to mutate immutable object`（3.5）、`implemented in both` 新版訊息（2.8）、weak 參考崩潰的停止原因（4.4）、`3-3-advanced-1` 擴容數字、10.3 匯入測試描述、11.5 Podfile 平台版本、11.6 `-force_load` 路徑。

**仍未驗證 / 留意**
- 只在模擬器驗證，沒有在實體 iPhone 上跑過；`testNullabilityAnnotationsPresent` 用 `__FILE__` 讀原始碼，實機會 `XCTSkip`。
- 崩潰訊息隨 iOS 版本略有差異（例如 `__NSArrayI` 越界在 iOS 26 / macOS 15 是 `__boundsFail`，較舊的系統是 `-[__NSArrayI objectAtIndex:]`；12-4-crash-3 用的是後者的格式）；題目裡的訊息以「讀得懂」為目的，不保證逐字等於每個版本。
- 效能面板的並行請求打真網路：舊網域 `api.frankfurter.app` 已改為 301 轉址，M10 / M11 已改用 `https://api.frankfurter.dev/v1`（2026-11-16 實測回 200，格式 `{"base":…,"rates":{…}}`，面板用的 USD / EUR / JPY / GBP / CNY 都有；歐洲央行資料沒有 TWD）。測試全用 stub，不受網路影響。
- `-Werror` 在 M12 的 `project.yml` 仍是註解（starter 共用同一份設定，學生寫到一半可能有警告）；solution 開啟後可建置。
- `.clang-format` 刻意未套用到程式碼（留給 12.5 練習）。
- Xcode 26 預設沒有 `iPhone 16` 模擬器；CLAUDE.md 的範例指令已改成 `iPhone 17`，其他版本以 `xcrun simctl list devices available` 為準。

