四個語言都有「只列方法、不給實作」的介面概念。差異在兩件事：Swift / Kotlin / Java 可以在介面裡放預設實作，Objective-C 不行；TypeScript 是結構型別（長得像就算），Objective-C 跟 Swift 一樣要明確宣告遵循。另一個 Objective-C 特有的東西是 `@optional`：TS 用 `?` 表達類似意思，其他三個語言沒有這個概念。

## Objective-C 怎麼寫

<Term en="protocol" tw="協定" cn="协议" jp="プロトコル" />是一組方法宣告，自己沒有實作，也不是類別。任何類別都可以宣告「我<Term en="conform" tw="遵循" cn="遵守" jp="準拠" />這個協定」，然後提供實作。帳本的觀察者協定長這樣：

```objc
@class LBLedger, LBTransaction;          // 前置宣告，避免互相 import

@protocol LBLedgerObserver <NSObject>

@required
- (void)ledger:(LBLedger *)ledger didAddTransaction:(LBTransaction *)tx;

@optional
- (void)ledgerDidReset:(LBLedger *)ledger;

@end
```

逐行讀：

- `@class LBLedger, LBTransaction;` 是<Term en="forward declaration" tw="前置宣告" cn="前向声明" jp="前方宣言" />。協定只需要知道「有這兩個類別」就能寫方法簽名，不用 `#import` 整個標頭檔。標頭檔之間互相 import 是 Objective-C 專案最常見的編譯錯誤來源，能前置宣告就前置宣告。
- `<NSObject>` 是協定繼承。`NSObject` 這裡指的是**協定**不是類別（兩者同名，是歷史包袱）。繼承它之後，`id<LBLedgerObserver>` 型別的變數才能呼叫 `respondsToSelector:`、`isEqual:`、`description` 這些基本方法而不被編譯器警告。**每個自己寫的協定都加 `<NSObject>`**，沒有例外。
- `@required` 是預設值，可以不寫，但寫出來讀者一眼看到分界。
- `@optional` 之後的方法，遵循者可以不實作。這是 delegate 模式的基礎（5.2），也是 crash 的主要來源（下面會講）。

### 遵循協定

在類別宣告的父類別後面加角括號：

```objc
@interface LBConsoleObserver : NSObject <LBLedgerObserver>
@end

@implementation LBConsoleObserver
- (void)ledger:(LBLedger *)ledger didAddTransaction:(LBTransaction *)tx {
    NSLog(@"新增：%@", tx.note);
}
// ledgerDidReset: 是 optional，不實作也能編譯
@end
```

少實作 `@required` 的方法，編譯器會給警告 `method 'ledger:didAddTransaction:' in protocol 'LBLedgerObserver' not implemented`。注意是**警告不是錯誤**，程式照樣能跑，直到有人呼叫那個方法。把專案設定 `-Werror` 或至少不要忽視這條警告。

遵循多個協定用逗號：`@interface LBReportViewController : UIViewController <UITableViewDataSource, UITableViewDelegate, LBLedgerObserver>`。

### `id<LBLedgerObserver>`：只關心協定，不關心類別

```objc
@property (nonatomic, weak, nullable) id<LBLedgerObserver> delegate;
```

`id<LBLedgerObserver>` 讀作「任何遵循 `LBLedgerObserver` 的物件」。編譯器允許你對它呼叫協定裡的方法，以及 `<NSObject>` 帶進來的方法；呼叫其他方法會警告。這就是 Objective-C 版的「依介面寫程式」。賦值時編譯器會檢查右邊的類別有沒有宣告遵循，沒有就警告 `assigning to 'id<LBLedgerObserver>' from incompatible type`。這點跟 TypeScript 不同：TS 只看方法長得像不像，Objective-C 要在 `@interface` 明寫。

如果你還需要類別的方法（例如只收 `UIView` 的子類別），可以寫 `UIView<LBLedgerObserver> *`。

### 呼叫 optional 方法前先問

```objc
- (void)reset {
    [_items removeAllObjects];
    if ([self.delegate respondsToSelector:@selector(ledgerDidReset:)]) {
        [self.delegate ledgerDidReset:self];
    }
}
```

`respondsToSelector:` 是<Term en="introspection" tw="內省" cn="内省" jp="イントロスペクション" />：執行期問物件「你有這個方法嗎」。optional 方法一律先問再呼叫，required 方法可以直接呼叫。另一個相關的方法是 `conformsToProtocol:`，問的是「你有沒有**宣告**遵循」：

```objc
if ([obj conformsToProtocol:@protocol(LBLedgerObserver)]) { ... }
```

注意它檢查的是宣告，不是實作。一個類別宣告了遵循卻漏實作 required 方法，`conformsToProtocol:` 仍回傳 `YES`，然後呼叫時 crash。所以 `conformsToProtocol:` 多用在型別判斷，`respondsToSelector:` 才是「呼叫前的保險」。

### 完整範例（可貼進 Scratch）

```objc
#import <Foundation/Foundation.h>

@class LBLedger;

@protocol LBLedgerObserver <NSObject>
@required
- (void)ledger:(LBLedger *)ledger didAddTransaction:(NSString *)note;
@optional
- (void)ledgerDidReset:(LBLedger *)ledger;
@end

@interface LBLedger : NSObject
@property (nonatomic, weak, nullable) id<LBLedgerObserver> delegate;
- (void)addNote:(NSString *)note;
- (void)reset;
@end

@implementation LBLedger {
    NSMutableArray<NSString *> *_notes;
}
- (instancetype)init {
    if (self = [super init]) { _notes = [NSMutableArray array]; }
    return self;
}
- (void)addNote:(NSString *)note {
    [_notes addObject:note];
    [self.delegate ledger:self didAddTransaction:note];   // required
}
- (void)reset {
    [_notes removeAllObjects];
    if ([self.delegate respondsToSelector:@selector(ledgerDidReset:)]) {
        [self.delegate ledgerDidReset:self];              // optional
    } else {
        NSLog(@"delegate 沒實作 ledgerDidReset:，略過");
    }
}
@end

@interface LBConsoleObserver : NSObject <LBLedgerObserver>
@end
@implementation LBConsoleObserver
- (void)ledger:(LBLedger *)ledger didAddTransaction:(NSString *)note {
    NSLog(@"新增：%@", note);
}
@end

int main(void) {
    @autoreleasepool {
        LBLedger *ledger = [LBLedger new];
        LBConsoleObserver *observer = [LBConsoleObserver new];
        ledger.delegate = observer;
        [ledger addNote:@"午餐"];
        [ledger reset];
        NSLog(@"%d", [observer conformsToProtocol:@protocol(LBLedgerObserver)]);
        NSLog(@"%d", [observer respondsToSelector:@selector(ledgerDidReset:)]);
    }
    return 0;
}
// 預期輸出：
// 新增：午餐
// delegate 沒實作 ledgerDidReset:，略過
// 1
// 0
```

最後兩行是重點：`conformsToProtocol:` 說「有宣告遵循」（1），`respondsToSelector:` 說「但沒有那個方法」（0）。兩個問題不一樣。

<Tip title="Swift 的預設實作在 ObjC 怎麼補">
Swift 的 `extension LedgerObserver { func ledgerDidReset(_:) {} }` 讓所有遵循者免費得到一個實作。Objective-C 的協定沒有這個能力。替代方案依序是：（1）把方法標 `@optional`，呼叫端用 `respondsToSelector:` 判斷，這是 Cocoa 的標準做法；（2）提供一個基底類別 `LBBaseObserver` 實作空方法讓人繼承；（3）在 `NSObject` 上寫分類（5.3）加那個方法，但這會污染所有物件，Apple 自己的框架偶爾這樣做，你最好不要。
</Tip>

<Pitfall title="協定裡的 @property 不會自動合成">
<Fragment slot="bad">
```objc
@protocol LBNamed <NSObject>
@property (nonatomic, copy, readonly) NSString *displayName;
@end

@interface LBCategory : NSObject <LBNamed>
@end
@implementation LBCategory
@end
// 警告：auto property synthesis will not synthesize property
// 'displayName' declared in protocol 'LBNamed'
// 執行時 [cat displayName] → unrecognized selector
```
</Fragment>
<Fragment slot="good">
```objc
@interface LBCategory : NSObject <LBNamed>
@property (nonatomic, copy, readonly) NSString *displayName; // 再宣告一次
@end
// 或在 @implementation 裡寫 @synthesize displayName = _displayName;
// 或直接實作 - (NSString *)displayName 方法
```
</Fragment>
協定裡的 `@property` 只是「宣告 getter / setter 方法」的縮寫，編譯器不會替遵循的類別產生實體變數。要自己在類別裡再宣告一次屬性、用 `@synthesize`、或手寫方法。
</Pitfall>

<Pitfall title="沒加 <NSObject> 的協定，連 respondsToSelector: 都不能叫">
`@protocol LBLedgerObserver` 後面漏掉 `<NSObject>`，`id<LBLedgerObserver> d` 就只知道協定裡的那幾個方法。寫 `[d respondsToSelector:...]` 會警告 `no known instance method for selector`，有人就把 `d` 轉型成 `id` 來閃掉警告，於是失去所有型別檢查。正解是回頭把 `<NSObject>` 加上。
</Pitfall>

<Pitfall title="標頭檔互相 import 造成的鬼打牆">
`LBLedger.h` import `LBLedgerObserver.h`，`LBLedgerObserver.h` 又 import `LBLedger.h`（因為方法參數用到 `LBLedger *`），結果是一堆 `expected a type` 錯誤，而且錯在你沒改過的檔案。標頭檔裡只要「知道有這個型別」就用 `@class` / `@protocol` 前置宣告，`#import` 留給 `.m`。協定的前置宣告寫法是 `@protocol LBLedgerObserver;`，之後就能宣告 `id<LBLedgerObserver>` 屬性。
</Pitfall>

<Crash message={`*** Terminating app due to uncaught exception 'NSInvalidArgumentException',
reason: '-[LBSettingsViewController ledgerDidReset:]: unrecognized selector sent to instance 0x7fb2c3d08f40'`}>
讀法：類別 `LBSettingsViewController`、selector `ledgerDidReset:`。這個類別遵循了 `LBLedgerObserver` 但沒有實作 optional 的 `ledgerDidReset:`，而 `LBLedger` 的 `reset` 直接呼叫 `[self.delegate ledgerDidReset:self]` 沒有先 `respondsToSelector:`。編譯器不會抓到：`id<LBLedgerObserver>` 型別允許你呼叫協定裡所有方法，optional 也算。修法在呼叫端，不在 delegate 端：每個 optional 方法呼叫前都加 `respondsToSelector:` 判斷。
</Crash>

## 小結

- `@protocol` 是一組方法宣告；`@required` 預設，`@optional` 可不實作。每個協定都繼承 `<NSObject>`。
- 類別在 `@interface` 的角括號裡宣告遵循；`id<Proto>` 是「任何遵循者」型別。遵循是明確宣告，不是結構比對。
- optional 方法呼叫前先 `respondsToSelector:`；`conformsToProtocol:` 只檢查宣告。
- Objective-C 的協定沒有預設實作；用 `@optional` + 檢查，或基底類別。
- 標頭檔裡用 `@class` / `@protocol` 前置宣告，`#import` 放進 `.m`。
