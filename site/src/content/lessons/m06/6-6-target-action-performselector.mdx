其他語言的事件回呼都是「存一個函式」。Objective-C 的 UIKit 誕生時沒有 block，所以存的是「一個物件（target）加一個方法名稱（action）」，事件來了用 6.2 的訊息派送送過去。`setTimeout` 對應 `performSelector:afterDelay:`，`fn.apply(obj, args)` 對應 `NSInvocation`。Swift 的 `#selector` 版 `addTarget` 底下仍是同一套。

## Objective-C 怎麼寫

### target-action：存一個物件、一個 selector

```objc
[saveButton addTarget:self
               action:@selector(saveTapped:)
     forControlEvents:UIControlEventTouchUpInside];

- (void)saveTapped:(UIButton *)sender { ... }
```

`UIControl` 內部存的就是 `(target, action, events)` 三元組；使用者放開手指時，它對 `target` 執行 `performSelector:action withObject:self`（實際是透過 `UIApplication sendAction:to:from:forEvent:`，多了 responder 鏈的查找：`target` 傳 `nil` 時沿 first responder 往上找第一個會回應 `action` 的物件）。<Term en="target-action" tw="目標-動作（target-action）" cn="目标-动作" jp="ターゲット・アクション" />的 action 可以是三種簽名之一：無參數、一個 `sender`、`sender` 加 `UIEvent`，UIKit 看 selector 有幾個冒號決定傳幾個。`UIBarButtonItem`、`UIGestureRecognizer`、`NSTimer`、`UIMenu` 的舊版 API 全是同一套。

因為存的是 selector，`target` 一律 `weak`（UIKit 內部如此），所以 ViewController 不會因為按鈕而活著；但也因為是 selector，改方法名忘了改 Storyboard 的連線，就是 6.2 的 `unrecognized selector`。

### performSelector 家族

```objc
[self performSelector:@selector(reload)];                       // 等於 [self reload]
[self performSelector:@selector(addNote:) withObject:@"午餐"];   // 一個物件參數
[self performSelector:@selector(set:for:) withObject:a withObject:b];  // 最多兩個

[self performSelector:@selector(recalcTotal)
           withObject:nil
           afterDelay:0.3];                                      // 延遲執行
[NSObject cancelPreviousPerformRequestsWithTarget:self
                                         selector:@selector(recalcTotal)
                                           object:nil];           // 取消還沒跑的
```

前三個是「用變數決定呼叫哪個方法」，只有 selector 真的是執行期才知道時才用（target-action、plugin）；知道名字就直接寫方括號。限制：參數**只收物件**，傳 `NSInteger` 得包成 `NSNumber` 而且對方的方法簽名也要收 `NSNumber`，最多兩個參數，回傳值是 `id`（基本型別回傳值得用 `NSInvocation`）。

`afterDelay:` 版本是 iOS 常見的「輸入防抖」寫法：每次輸入先 `cancelPrevious...` 再重新排一次，0.3 秒內沒有新輸入才會真的重算。它把訊息排進**當前執行緒的**<Term en="run loop" tw="執行迴圈（RunLoop）" cn="运行循环" jp="ランループ" />，所以在沒有 run loop 的背景執行緒（GCD 的 global queue）呼叫它，永遠不會執行；主執行緒沒問題。另外它會 retain `target` 直到執行或取消，`dealloc` 裡記得取消。GCD 時代可以用 `dispatch_after` 取代，但 `dispatch_after` 不能取消，防抖還是 `performSelector:afterDelay:` 方便（模組 10 會用 `DispatchWorkItem` 等效寫法再做一次）。

### ARC 的 leak 警告

```objc
SEL action = ...;
[target performSelector:action];
// warning: PerformSelector may cause a leak because its selector is unknown
```

ARC 要知道每個方法的回傳值是不是「要你負責釋放的物件」（`alloc` / `new` / `copy` 開頭的方法回傳的是），它靠方法名稱判斷。selector 存在變數裡，編譯期看不到名字，ARC 就不知道要不要 release 回傳值，所以警告。你確定這個 selector 回傳 `void` 或不需要你負責的物件時，壓掉它：

```objc
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Warc-performSelector-leaks"
[target performSelector:action withObject:sender];
#pragma clang diagnostic pop
```

把 `push` / `pop` 包緊一點，只蓋住那一行。另一個不需要 pragma 的寫法是用 IMP 直接呼叫：

```objc
IMP imp = [target methodForSelector:action];
void (*func)(id, SEL, id) = (void *)imp;
func(target, action, sender);         // 型別寫清楚了，ARC 不用猜
```

### NSInvocation：多參數與基本型別

```objc
SEL sel = @selector(addAmount:note:flag:);
NSMethodSignature *sig = [ledger methodSignatureForSelector:sel];
NSInvocation *inv = [NSInvocation invocationWithMethodSignature:sig];
inv.target = ledger;
inv.selector = sel;
NSDecimalNumber *amount = [NSDecimalNumber decimalNumberWithString:@"120"];
NSString *note = @"午餐";
BOOL flag = YES;
[inv setArgument:&amount atIndex:2];    // 0 是 self、1 是 _cmd，參數從 2 開始
[inv setArgument:&note atIndex:3];
[inv setArgument:&flag atIndex:4];      // 基本型別也行：傳位址
[inv invoke];
NSUInteger count;
[inv getReturnValue:&count];            // 回傳值也是寫進你給的位址
```

<Term en="invocation" tw="呼叫物件（NSInvocation）" cn="调用对象" jp="インボケーション" />是「一次方法呼叫」的物件化：目標、selector、每個參數、回傳值都在裡面，可以存起來、改參數、延後執行、在別的執行緒 `invoke`。6.2 的 `forwardInvocation:` 交給你的就是它。要先有 `NSMethodSignature`（參數個數與<Term en="type encoding" tw="型別編碼" cn="类型编码" jp="型エンコーディング" />），所以目標類別得真的有這個方法，或你自己用 `signatureWithObjCTypes:` 造一個。`setArgument:` 收的是**位址**，物件參數也要 `&amount`，這是最常寫錯的地方。回傳物件時 `getReturnValue:` 不會 retain，ARC 下要把接收變數標成 `__unsafe_unretained` 或先轉成 `void *` 再橋接，不然會多 release 一次。

### 完整範例（可貼進 Scratch）

```objc
#import <Foundation/Foundation.h>

// 用 NSObject 模擬 UIControl 的 target-action
@interface LBButton : NSObject
@property (nonatomic, weak) id target;
@property (nonatomic, assign) SEL action;
- (void)tap;
@end
@implementation LBButton
- (void)tap {
    if (![_target respondsToSelector:_action]) {
        NSLog(@"target 不回應 %@", NSStringFromSelector(_action));
        return;
    }
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Warc-performSelector-leaks"
    [_target performSelector:_action withObject:self];
#pragma clang diagnostic pop
}
@end

@interface LBLedger : NSObject
@property (nonatomic, strong) NSDecimalNumber *total;
- (void)saveTapped:(LBButton *)sender;
- (NSUInteger)addAmount:(NSDecimalNumber *)amount note:(NSString *)note flag:(BOOL)flag;
- (void)recalc;
@end
@implementation LBLedger
- (instancetype)init { if (self = [super init]) _total = NSDecimalNumber.zero; return self; }
- (void)saveTapped:(LBButton *)sender { NSLog(@"儲存，sender 是 %@", [sender class]); }
- (NSUInteger)addAmount:(NSDecimalNumber *)amount note:(NSString *)note flag:(BOOL)flag {
    self.total = [_total decimalNumberByAdding:amount];
    NSLog(@"加入 %@（%@，flag=%d）", amount, note, flag);
    return 42;
}
- (void)recalc { NSLog(@"重算 total = %@", _total); }
@end

int main(void) {
    @autoreleasepool {
        LBLedger *ledger = [LBLedger new];

        // 1. target-action
        LBButton *button = [LBButton new];
        button.target = ledger;
        button.action = @selector(saveTapped:);
        [button tap];
        button.action = NSSelectorFromString(@"saveTapped");   // 少了冒號
        [button tap];

        // 2. NSInvocation：三個參數含 BOOL，讀 NSUInteger 回傳值
        SEL sel = @selector(addAmount:note:flag:);
        NSInvocation *inv = [NSInvocation invocationWithMethodSignature:
                             [ledger methodSignatureForSelector:sel]];
        inv.target = ledger; inv.selector = sel;
        NSDecimalNumber *amount = [NSDecimalNumber decimalNumberWithString:@"120"];
        NSString *note = @"午餐"; BOOL flag = YES;
        [inv setArgument:&amount atIndex:2];
        [inv setArgument:&note atIndex:3];
        [inv setArgument:&flag atIndex:4];
        [inv invoke];
        NSUInteger result = 0;
        [inv getReturnValue:&result];
        NSLog(@"回傳 %lu", (unsigned long)result);

        // 3. afterDelay 與取消：需要 run loop
        [ledger performSelector:@selector(recalc) withObject:nil afterDelay:0.1];
        [ledger performSelector:@selector(recalc) withObject:nil afterDelay:0.2];
        [NSObject cancelPreviousPerformRequestsWithTarget:ledger
                                                 selector:@selector(recalc)
                                                   object:nil];   // 兩個都取消
        [ledger performSelector:@selector(recalc) withObject:nil afterDelay:0.1];
        [[NSRunLoop currentRunLoop] runUntilDate:[NSDate dateWithTimeIntervalSinceNow:0.3]];
        NSLog(@"結束");
    }
    return 0;
}
// 預期輸出：
// 儲存，sender 是 LBButton
// target 不回應 saveTapped
// 加入 120（午餐，flag=1）
// 回傳 42
// 重算 total = 120
// 結束
```

把最後的 `runUntilDate:` 那行拿掉，`重算` 不會印出來：命令列程式的主執行緒沒有在跑 run loop，`afterDelay:` 排進去的訊息沒人處理。iOS App 的主執行緒永遠在跑 run loop，所以你平常不會注意到這個依賴，直到在 `dispatch_async` 的背景 block 裡用了它。

<Tip title="現代寫法：什麼時候還會碰到這些">
新程式碼用 block（`UIAction`、`dispatch_after`、`NSTimer scheduledTimerWithTimeInterval:repeats:block:`）就好。你會在三個地方碰到本章內容：接手舊專案（Storyboard 連線、`performSelector:afterDelay:` 防抖）、寫 UIKit 子類別或自訂控制項（要自己 `sendActionsForControlEvents:`）、以及實作 6.2 的 `forwardInvocation:` 或單元測試框架那種「用字串找方法並呼叫」的工具。看懂比會寫重要。
</Tip>

<Pitfall title="performSelector: 傳基本型別">
<Fragment slot="bad">
```objc
[self performSelector:@selector(setCount:) withObject:(id)5];   // 把 5 當指標
[self performSelector:@selector(setRatio:) withObject:@(0.5)];  // 方法收 double，拿到的是指標
```
</Fragment>
<Fragment slot="good">
```objc
[self setCount:5];                                     // 知道名字就直接呼叫
// 真的要動態：NSInvocation setArgument:&value atIndex:2
```
</Fragment>
`withObject:` 的參數型別是 `id`，傳進去的位元會原封不動放到對方的參數位置。對方收 `NSInteger` 時拿到的是 `NSNumber` 的位址值，收 `double` 時更是垃圾。基本型別一律 `NSInvocation` 或直接呼叫。
</Pitfall>

<Pitfall title="afterDelay 在背景執行緒永遠不執行">
`dispatch_async(dispatch_get_global_queue(0, 0), ^{ [self performSelector:@selector(save) withObject:nil afterDelay:1]; });` 什麼都不會發生，也沒有錯誤。GCD 的工作執行緒沒有 run loop。要延遲就在主佇列呼叫，或改用 `dispatch_after`。同理 `NSTimer scheduledTimer...` 在背景執行緒也不會走。
</Pitfall>

<Pitfall title="dealloc 前沒取消 afterDelay">
`performSelector:afterDelay:` 會 retain `target` 直到執行，所以 ViewController 關掉後還會多活幾秒，然後在 `self` 已經離開畫面時執行 `reloadData`。通常不 crash 但會出現「關掉的頁面還在跑網路請求」這類鬼現象。在 `viewWillDisappear:` 或 `dealloc` 呼叫 `cancelPreviousPerformRequestsWithTarget:self`（不帶 selector 的版本會取消所有排給 `self` 的）。
</Pitfall>

## 小結

- target-action = 存 `(target, action)`，事件來時用訊息派送送 selector；action 可有 0 / 1 / 2 個參數；改名忘了改 IB 連線就是 `unrecognized selector`。
- `performSelector:withObject:` 只收物件、最多兩個參數；知道名字就直接呼叫，只在 selector 真的動態時用。
- `performSelector:afterDelay:` 依賴當前執行緒的 run loop，背景執行緒不會執行；會 retain target，用 `cancelPreviousPerformRequestsWithTarget:` 取消。
- ARC 的 `-Warc-performSelector-leaks` 用 `#pragma clang diagnostic push / ignored / pop` 包住那一行壓掉，或改用 IMP 函式指標。
- `NSInvocation` 處理多參數與基本型別：參數從索引 2 開始、`setArgument:` 與 `getReturnValue:` 都傳位址。
