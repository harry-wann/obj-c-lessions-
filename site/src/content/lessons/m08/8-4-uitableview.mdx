## Objective-C 怎麼寫

### dataSource 與 delegate 的分工

<Term en="table view" tw="表格視圖" cn="表视图" jp="テーブルビュー" />自己不知道資料長什麼樣，它問兩個協定：`UITableViewDataSource` 回答「有幾個 section、每個幾列、第 n 列長什麼樣」，`UITableViewDelegate` 回答「點了怎麼辦、列多高、header 是什麼 view、能不能滑動刪除」。`UITableViewController` 已經把自己設成兩者，直接覆寫方法就好；一般 `UIViewController` 裡放表格要自己設 `tableView.dataSource = self; tableView.delegate = self;`（兩個都是 weak，5.2）。

```objc
// LBTransactionListViewController.m
#import "LBTransactionListViewController.h"
#import "LBTransactionCell.h"
#import "LBMonthHeaderView.h"
#import "LBTransactionViewModel.h"
#import "LBLedger.h"
#import "LBMonthSection.h"
#import "LBTransaction.h"
#import "LBUndoStack.h"

static NSString * const kCellID = @"LBTransactionCell";
static NSString * const kHeaderID = @"LBMonthHeaderView";

@interface LBTransactionListViewController ()
@property (nonatomic, strong) LBLedger *ledger;
@property (nonatomic, strong) LBUndoStack *undoStack;
@property (nonatomic, copy) NSArray<LBMonthSection *> *sections;
@end

@implementation LBTransactionListViewController

- (instancetype)initWithLedger:(LBLedger *)ledger undoStack:(LBUndoStack *)undoStack {
    if (self = [super initWithStyle:UITableViewStyleInsetGrouped]) {
        _ledger = ledger;
        _undoStack = undoStack;
    }
    return self;
}

- (void)viewDidLoad {
    [super viewDidLoad];
    self.title = @"帳本";
    [self.tableView registerClass:[LBTransactionCell class]
           forCellReuseIdentifier:kCellID];
    [self.tableView registerClass:[LBMonthHeaderView class]
        forHeaderFooterViewReuseIdentifier:kHeaderID];
    self.tableView.rowHeight = 64;
    self.tableView.sectionHeaderHeight = 44;
    [self reloadSections];
}

- (void)reloadSections {
    self.sections = [self.ledger transactionsGroupedByMonth];
    self.tableView.backgroundView = self.sections.count == 0 ? [self makeEmptyView] : nil;
}

#pragma mark - UITableViewDataSource

- (NSInteger)numberOfSectionsInTableView:(UITableView *)tableView {
    return self.sections.count;
}

- (NSInteger)tableView:(UITableView *)tableView
 numberOfRowsInSection:(NSInteger)section {
    return self.sections[section].transactions.count;
}

- (UITableViewCell *)tableView:(UITableView *)tableView
         cellForRowAtIndexPath:(NSIndexPath *)indexPath {
    LBTransactionCell *cell =
        [tableView dequeueReusableCellWithIdentifier:kCellID forIndexPath:indexPath];
    LBTransaction *tx = self.sections[indexPath.section].transactions[indexPath.row];
    [cell configureWithViewModel:[LBTransactionViewModel viewModelWithTransaction:tx]];
    return cell;
}

#pragma mark - UITableViewDelegate

- (UIView *)tableView:(UITableView *)tableView
    viewForHeaderInSection:(NSInteger)section {

```

`registerClass:forCellReuseIdentifier:` 告訴表格「這個識別字對應這個類別」，之後 `dequeueReusableCellWithIdentifier:forIndexPath:` 有閒置的 cell 就回收給你，沒有就用 `initWithStyle:reuseIdentifier:` 建一個，**永遠不回 nil**。舊 API `dequeueReusableCellWithIdentifier:`（沒有 `forIndexPath:`）會回 nil，舊專案裡你會看到 `if (cell == nil) { cell = [[... alloc] init...]; }` 的樣板，那是 iOS 6 以前的寫法。

### 自訂 cell 與 prepareForReuse

cell 被回收時可能還留著上一筆的內容：紅色金額、勾勾、展開狀態。兩個防線：

```objc
// LBTransactionCell.m（接 8.3）
- (void)prepareForReuse {
    [super prepareForReuse];
    _iconView.image = nil;
    _titleLabel.text = nil;
    _subtitleLabel.text = nil;
    _amountLabel.text = nil;
    _amountLabel.textColor = UIColor.labelColor;
    self.accessoryType = UITableViewCellAccessoryNone;
}
```

第一道是 `configureWithViewModel:` **每個欄位都設**，包含「這筆沒有」的欄位（`note` 為空就設 `@""` 而不是跳過）；第二道是 `prepareForReuse` 清回預設。只靠第二道不夠：非同步載入圖片的 cell 在回收後圖片才回來，還是會貼到錯的列，要在回呼裡比對 identifier。`testCellResetsAllFields` 測的就是第一道：先用一筆支出設定、再用一筆沒有分類的收入設定同一個 cell，所有欄位都要是後者的值。

`LBTransactionViewModel` 把顯示字串預先算好（金額格式化、日期字串），`cellForRowAtIndexPath:` 只做賦值。這個方法一秒會被叫幾十次，裡面建 `NSDateFormatter` 會掉幀（10.2 會量）。

### 滑動刪除與局部更新

```objc
- (void)tableView:(UITableView *)tableView
    commitEditingStyle:(UITableViewCellEditingStyle)editingStyle
     forRowAtIndexPath:(NSIndexPath *)indexPath {
    if (editingStyle != UITableViewCellEditingStyleDelete) return;

    LBTransaction *tx = self.sections[indexPath.section].transactions[indexPath.row];
    BOOL sectionWillVanish = self.sections[indexPath.section].transactions.count == 1;

    [self.ledger removeTransactionWithIdentifier:tx.identifier];   // 1. 先改資料
    self.sections = [self.ledger transactionsGroupedByMonth];       // 2. 重算模型

    __weak typeof(self) weakSelf = self;
    [self.undoStack registerUndo:^{ [weakSelf.ledger addTransaction:tx];
                                    [weakSelf reloadSections];
                                    [weakSelf.tableView reloadData]; }
                            redo:^{ [weakSelf.ledger removeTransactionWithIdentifier:tx.identifier];
                                    [weakSelf reloadSections];
                                    [weakSelf.tableView reloadData]; }];

    [tableView performBatchUpdates:^{                              // 3. 再改畫面
        if (sectionWillVanish) {
            [tableView deleteSections:[NSIndexSet indexSetWithIndex:indexPath.section]
                     withRowAnimation:UITableViewRowAnimationFade];
        } else {
            [tableView deleteRowsAtIndexPaths:@[ indexPath ]
                             withRowAnimation:UITableViewRowAnimationFade];
        }
    } completion:^(BOOL finished) {
        [weakSelf reloadSections];                                  // 4. header 合計與空狀態
        if (!sectionWillVanish) {
            [tableView reloadSections:[NSIndexSet indexSetWithIndex:indexPath.section]
                     withRowAnimation:UITableViewRowAnimationNone];
        }
    }];
}
```

鐵律：**資料先改、畫面後改，而且兩邊的差異要一致**。`deleteRowsAtIndexPaths:` 之後表格會重新問 `numberOfRowsInSection:`，數字必須剛好少一；不一致就是本章第二個崩潰現場。`performBatchUpdates:` 把多個 insert / delete 包成一次動畫，裡面的 index path 全部以更新前的狀態計算。只改一筆就用局部更新，動畫順、不會跳回頂端；資料整批換掉（切換月份、搜尋結果）才用 `reloadData`。

畫面 09 的「滑動刪除與確認」用 iOS 11 以後的 `tableView:trailingSwipeActionsConfigurationForRowAtIndexPath:` 回一個 `UISwipeActionsConfiguration`，刪除前跳 `UIAlertController` 確認（8.6），確認後走同一段邏輯。`commitEditingStyle:` 是舊 API，兩者都要認得，舊專案只有前者。

### reloadData、局部更新與 DiffableDataSource

| 方法 | 什麼時候 | 代價 |
|---|---|---|
| `reloadData` | 資料整批換、不知道差了什麼 | 沒動畫、捲動位置可能跳、所有可見 cell 重建 |
| `insertRows` / `deleteRows` / `reloadRows` + `performBatchUpdates:` | 知道差了哪幾筆 | 有動畫；數量算錯就 crash |
| `UITableViewDiffableDataSource`（iOS 13） | 不想自己算差異 | 給它新 snapshot，它算 diff 並動畫；model 要能 hash / isEqual（3.4） |

Diffable 的用法是 `NSDiffableDataSourceSnapshot` → `appendSectionsWithIdentifiers:` → `appendItemsWithIdentifiers:` → `applySnapshot:animatingDifferences:`，概念就是 React 的虛擬 DOM diff。本章先用手動更新把「數量要一致」的規則練進手裡，延伸題 3 再改寫成 Diffable 比較。

### 樹：分類階層攤平成有深度的列表

畫面 05 的分類選擇是一棵<Term en="tree" tw="樹" cn="树" jp="木" />：「飲食」底下有「早餐 / 午餐 / 晚餐」，每個節點是 `LBCategory`，`parent` weak、`children` strong（4.3 的鏈結方向）。表格是一維的，所以要把樹**攤平**成一個陣列，每個元素帶著自己的深度決定縮排。<Term en="depth-first traversal" tw="深度優先走訪" cn="深度优先遍历" jp="深さ優先探索" />用遞迴寫最自然：先放自己，再依序走每個子節點。

```objc
// LBCategory.m 新增
- (NSArray<LBCategory *> *)flattenedWithExpanded:(NSSet<NSString *> *)expandedIDs {
    NSMutableArray<LBCategory *> *result = [NSMutableArray array];
    [self lb_flattenInto:result expanded:expandedIDs];
    return [result copy];
}

- (void)lb_flattenInto:(NSMutableArray<LBCategory *> *)result
              expanded:(NSSet<NSString *> *)expandedIDs {
    [result addObject:self];                                 // 前序：先自己
    if (![expandedIDs containsObject:self.identifier]) return;   // 收合就不往下
    for (LBCategory *child in self.children) {
        [child lb_flattenInto:result expanded:expandedIDs];  // 遞迴
    }
}
```

```objc
// LBCategoryPickerViewController.m（核心）
- (void)rebuildRows {
    NSMutableArray *rows = [NSMutableArray array];
    for (LBCategory *root in self.roots) {
        [rows addObjectsFromArray:[root flattenedWithExpanded:self.expandedIDs]];
    }
    self.visibleRows = rows;
}

- (UITableViewCell *)tableView:(UITableView *)tableView
         cellForRowAtIndexPath:(NSIndexPath *)indexPath {
    UITableViewCell *cell = [tableView dequeueReusableCellWithIdentifier:@"Category"
                                                            forIndexPath:indexPath];
    LBCategory *c = self.visibleRows[indexPath.row];
    cell.textLabel.text = c.name;
    cell.indentationLevel = (NSInteger)c.depth;     // 縮排 = depth × indentationWidth
    cell.indentationWidth = 20;
    cell.imageView.image = [UIImage systemImageNamed:c.symbolName];
    cell.accessoryType = c.children.count > 0 ? UITableViewCellAccessoryDisclosureIndicator
                                              : UITableViewCellAccessoryNone;
    cell.accessoryType = [c isEqual:self.selected] ? UITableViewCellAccessoryCheckmark
                                                   : cell.accessoryType;
    return cell;
}

- (void)toggleExpansionOf:(LBCategory *)category {
    NSArray *before = self.visibleRows;
    if ([self.expandedIDs containsObject:category.identifier]) {
        [self.expandedIDs removeObject:category.identifier];
    } else {
        [self.expandedIDs addObject:category.identifier];
    }
    [self rebuildRows];
    // 進階：比對 before / visibleRows 算出要 insert / delete 的 index path 做局部更新
    [self.tableView reloadData];
}
```

複雜度：攤平走訪每個節點一次，O(n)；遞迴深度等於樹的高度，分類樹只有兩三層，不用擔心堆疊。「尋找路徑」（麵包屑「飲食 › 午餐」）反過來走 `parent` 到根，O(高度)。進階練習要你把 `toggleExpansionOf:` 從 `reloadData` 改成 `performBatchUpdates:`：展開時插入的列數就是 `flattenedWithExpanded:` 之後多出來的那段。

### 二元搜尋：新交易該插在哪

帳本的 `transactions` 依日期倒序，新增一筆時不該整個重排（O(n log n)），而是找到插入點 O(log n) 再 `insertObject:atIndex:`（搬移 O(n)，但常數小）。<Term en="binary search" tw="二元搜尋" cn="二分查找" jp="二分探索" />：

```objc
// 手寫版：回傳第一個「date 早於或等於 tx.date」的索引（倒序陣列）
NSUInteger LBInsertionIndex(NSArray<LBTransaction *> *sorted, LBTransaction *tx) {
    NSUInteger lo = 0, hi = sorted.count;          // 半開區間 [lo, hi)
    while (lo < hi) {
        NSUInteger mid = lo + (hi - lo) / 2;       // 不寫 (lo+hi)/2，避免溢位
        if ([sorted[mid].date compare:tx.date] == NSOrderedDescending) {
            lo = mid + 1;                          // mid 比較新，答案在右邊
        } else {
            hi = mid;
        }
    }
    return lo;
}

// Foundation 現成版：同一件事
NSUInteger idx = [sorted indexOfObject:tx
                         inSortedRange:NSMakeRange(0, sorted.count)
                               options:NSBinarySearchingInsertionIndex |
                                       NSBinarySearchingFirstEqual
                       usingComparator:^NSComparisonResult(LBTransaction *a, LBTransaction *b) {
                           return [b.date compare:a.date];   // 倒序：b 跟 a 反過來
                       }];
```

兩個版本都要會：手寫版面試會問，`indexOfObject:inSortedRange:options:usingComparator:` 工作上直接用。`options` 的三個旗標：`NSBinarySearchingInsertionIndex` 回插入點（找不到也回位置，不是 `NSNotFound`）、`FirstEqual` / `LastEqual` 決定同一天的新交易排在同日的最前還是最後。前提永遠是陣列已經依同一個 comparator 排好，否則結果是垃圾。

## 小結

- dataSource 回答「有什麼」、delegate 回答「怎麼互動」，兩個都 weak；`UITableViewController` 已經設好。
- `registerClass:` 一次，`dequeueReusableCellWithIdentifier:forIndexPath:` 永不回 nil；cell 會被重用，綁定時**每個欄位每個分支都設**，`prepareForReuse` 當保險。
- 資料先改、畫面後改、差異一致；一筆用 `performBatchUpdates:` 局部更新，整批用 `reloadData`，不想算 diff 用 `DiffableDataSource`。
- 樹用遞迴前序走訪攤平成帶深度的陣列，`indentationLevel = depth`；路徑沿 `parent` 往上找。
- 二元搜尋 `[lo, hi)` 半開區間、`mid = lo + (hi - lo) / 2`；Foundation 版是 `indexOfObject:inSortedRange:options:usingComparator:` 加 `NSBinarySearchingInsertionIndex`。
- Android：Adapter ↔ dataSource、ViewHolder ↔ cell、`onBindViewHolder` ↔ `cellForRowAtIndexPath:`，重用規則完全相同。
