## Objective-C 怎麼寫

### push / pop：有來有回的堆疊

<Term en="navigation controller" tw="導覽控制器" cn="导航控制器" jp="ナビゲーションコントローラ" />就是 5.5 的堆疊：`pushViewController:animated:` 推一頁、`popViewControllerAnimated:` 彈回上一頁、`popToRootViewControllerAnimated:` 回到底。每個被 push 進去的 VC 都能透過 `self.navigationController` 拿到它，導覽列的返回鍵自動出現，標題來自各 VC 的 `title`。

```objc
// LBTransactionEditorViewController.m：點分類那一列
- (void)showCategoryPicker {
    LBCategoryPickerViewController *picker =
        [[LBCategoryPickerViewController alloc] initWithRootCategories:[LBCategory defaultTree]
                                                              selected:self.category];
    __weak typeof(self) weakSelf = self;
    picker.onSelect = ^(LBCategory *category) {
        weakSelf.category = category;                 // 往回：block
        [weakSelf.navigationController popViewControllerAnimated:YES];
    };
    [self.navigationController pushViewController:picker animated:YES];
}
```

### present / dismiss：另起一疊

`presentViewController:animated:completion:` 從下方蓋上一個新的畫面層，`dismissViewControllerAnimated:completion:` 收掉。iOS 13 以後預設是卡片式 sheet（`UIModalPresentationPageSheet`），可以下滑關閉；全螢幕要明寫 `modalPresentationStyle = UIModalPresentationFullScreen`。被 present 的 VC **沒有導覽列**，要有標題、取消、儲存按鈕，就先包一層 `UINavigationController`：

```objc
// LBTransactionListViewController.m
- (void)addTapped {
    LBTransactionEditorViewController *editor =
        [[LBTransactionEditorViewController alloc] initWithLedger:self.ledger
                                                      transaction:nil];   // nil = 新增
    editor.delegate = self;                                             // 往回：delegate
    UINavigationController *nav =
        [[UINavigationController alloc] initWithRootViewController:editor];
    nav.modalPresentationStyle = UIModalPresentationPageSheet;
    [self presentViewController:nav animated:YES completion:nil];
}

#pragma mark - LBTransactionEditorDelegate

- (void)editor:(LBTransactionEditorViewController *)editor
    didSaveTransaction:(LBTransaction *)transaction {
    [self.ledger addTransaction:transaction];
    [self reloadSections];
    [self.tableView reloadData];          // 進階：算出 index path 用 insertRows
    [editor dismissViewControllerAnimated:YES completion:nil];
}

- (void)editorDidCancel:(LBTransactionEditorViewController *)editor {
    [editor dismissViewControllerAnimated:YES completion:nil];
}
```

誰來 dismiss？慣例是 **present 的那一方**（這裡是列表）在 delegate 方法裡收掉，編輯頁不用知道自己是被 present 還是被 push，重用性比較好。對被包在 nav 裡的 VC 呼叫 `dismiss`，UIKit 會往上找到被 present 的那個 nav 一起收掉。

### 往前傳值：指定初始化器或屬性注入

```objc
// LBTransactionEditorViewController.h
@interface LBTransactionEditorViewController : UIViewController
- (instancetype)initWithLedger:(LBLedger *)ledger
                   transaction:(nullable LBTransaction *)transaction NS_DESIGNATED_INITIALIZER;
@property (nonatomic, weak) id<LBTransactionEditorDelegate> delegate;
@end
```

兩種寫法：**指定初始化器**（2.x）把必要的依賴放進 `init`，少一個就編譯不過，缺點是 Storyboard 建的 VC 沒辦法走這條路；**屬性注入**（`editor.ledger = ledger;`）彈性大、Storyboard 可用（8.7 的 `prepareForSegue:` 只能這樣），缺點是忘了設就是 nil 一路傳下去。小帳本程式碼建的 VC 一律指定初始化器，Storyboard 建的設定頁用屬性注入。不要用的方法：全域單例一把抓（測不了）、`NSNotificationCenter` 傳值（有去無回，誰收到都不知道）。

### 往回傳值：delegate 或 block

| | delegate（5.2） | block（5.4） |
|---|---|---|
| 適合 | 多個事件（儲存 / 取消 / 刪除）、長期關係 | 單一事件、一次性回呼 |
| 寫法 | 協定 + `weak` 屬性 + 多個方法 | 一個 `copy` 屬性 |
| 陷阱 | 屬性寫成 `strong` 循環 | block 捕獲 `self` 循環（要 weakSelf） |
| 小帳本 | 編輯頁 `LBTransactionEditorDelegate` | 分類選擇 `onSelect` |

共通點：**不要**想從 `present` 拿回傳值。`present` 立刻回傳，使用者按下儲存是幾秒後的事，這是 5.6 講的非同步 API 慣例，傳值一定走回呼。Android 的 `startActivityForResult` → `onActivityResult` 也是同樣的拆法。

### UITabBarController

8.1 已經組過：`tabs.viewControllers = @[ ledgerNav, statsNav, settingsNav ]`，每個分頁各自一個 `UINavigationController`，分頁之間的堆疊獨立。`tabBarItem` 設在 nav 上（不是 nav 裡的 VC），因為 tab bar 看的是它的直接子 VC。`selectedIndex` 可以程式切換；`UITabBarControllerDelegate` 的 `shouldSelectViewController:` 能攔住切換（例如未儲存的表單）。

<Pitfall title="想從 present 直接拿回傳值">
`[self presentViewController:editor ...]; LBTransaction *tx = editor.result;` 讀到的永遠是 nil：present 立刻回傳，使用者還沒開始輸入。回傳值走 delegate 或 block，在回呼裡再動資料。同一個錯誤的 Android 版是 `startActivity` 之後馬上讀 extras。

<Pitfall title="delegate 設在錯的物件上">
包了 nav 之後寫 `nav.delegate = self` 或忘了設 `editor.delegate`：儲存按鈕按下去沒反應、也不 crash（對 nil 送訊息）。delegate 設在真正發事件的 VC 上；`UINavigationController` 自己的 `delegate` 是另一個協定（`UINavigationControllerDelegate`），管轉場。寫完回呼先放一個 NSLog 或斷點確認有被叫到。
</Pitfall>

## 小結

- `push` / `pop` 是堆疊，返回鍵自動；`present` / `dismiss` 另起一疊，預設卡片 sheet，要導覽列就先包 `UINavigationController`。
- 往前傳值：程式碼建的 VC 用指定初始化器，Storyboard 建的用屬性注入；不用單例、不用通知。
- 往回傳值：多事件用 delegate（weak）、單事件用 block（copy + weakSelf）；永遠不是 `present` 的回傳值。
- 由 present 的那一方在回呼裡 dismiss；`tabBarItem` 設在 nav 上。
- Android：`Intent` extras ↔ 初始化器參數、`ActivityResult` ↔ delegate；React：props ↔ 注入、callback ↔ delegate / block。
