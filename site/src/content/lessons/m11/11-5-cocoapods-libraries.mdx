## Objective-C 怎麼寫

### Podfile 三件組

<Term en="dependency manager" tw="相依性管理工具" cn="依赖管理器" jp="依存関係マネージャ" /> CocoaPods 是 Ruby 寫的，`Podfile` 是一段 Ruby DSL：

```ruby
# Podfile
platform :ios, '17.0'
inhibit_all_warnings!            # 第三方庫的警告不要淹掉自己的

target 'LittleBook' do
  pod 'Masonry', '~> 1.1'        # 1.1.x 任何版本，不升到 1.2
  pod 'FMDB', '2.7.5'            # 精確鎖定
  pod 'YYModel', '>= 1.0.4', '< 2.0'

  target 'LittleBookTests' do
    inherit! :search_paths       # 測試 target 看得到主 target 的 pod
  end
end

post_install do |installer|      # 常見：統一所有 pod 的 deployment target
  installer.pods_project.targets.each do |t|
    t.build_configurations.each do |c|
      c.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = '13.0'
    end
  end
end
```

版本寫法：`'1.1.0'` 精確；`'~> 1.1'` 樂觀鎖（≥ 1.1、&lt; 2.0）；`'~> 1.1.0'`（≥ 1.1.0、&lt; 1.2）；不寫版本 = 最新，**不要這樣寫**。

<Steps title="從零到跑起來">
<ol>
<li>終端機 <code>cd</code> 到 <code>.xcodeproj</code> 所在目錄，<code>pod init</code> 產生 Podfile 骨架（已有 Podfile 就跳過）。</li>
<li>編輯 Podfile 加入 <code>pod 'Masonry', '~&gt; 1.1'</code>。</li>
<li><code>pod install</code>。第一次會下載 spec 索引（CDN），然後產生 <code>Pods/</code>、<code>Podfile.lock</code>、<code>LittleBook.xcworkspace</code>。</li>
<li><strong>關掉</strong>開著的 <code>LittleBook.xcodeproj</code>，改開 <code>LittleBook.xcworkspace</code>（終端機 <code>open LittleBook.xcworkspace</code>）。</li>
<li>⌘B。第一次會先編所有 pod（<code>Pods</code> 專案裡的 target），之後就快了。</li>
<li>在 <code>.m</code> 寫 <code>#import &lt;Masonry/Masonry.h&gt;</code>（或 <code>@import Masonry;</code>），⌘R。</li>
<li><code>git add Podfile Podfile.lock</code> 一起 commit；<code>Pods/</code> 依團隊決定（見 Tip）。</li>
</ol>
</Steps>

### pod install 與 pod update 的差別

這是面試必問、工作上必踩：

| | `pod install` | `pod update [PodName]` |
|---|---|---|
| 讀 `Podfile.lock`？ | **讀**：lock 裡有的 pod 用 lock 的版本 | **不讀**（指定的那個 pod）：解析 Podfile 允許的最新版 |
| 什麼時候用 | clone 專案後、Podfile 加減 pod 後、CI | 刻意要升某個庫 |
| 改 `Podfile.lock`？ | 只在新加的 pod 加一行 | 會改被升級的版本號 |

<Term en="Podfile.lock" tw="鎖定檔" cn="锁定文件" jp="ロックファイル" /> 的意義是「全隊、CI、半年後的你，裝到的都是同一組版本」。它**一定進版控**；看到 `.gitignore` 裡有 `Podfile.lock` 的專案，第一天就把它拿出來。`Pods/` 目錄則兩派：進版控（clone 即建置、離線可用、CocoaPods 官方推薦）vs 不進（repo 小、diff 乾淨）；接手專案就跟原本的決定。

### 為什麼要開 .xcworkspace

`pod install` 產生一個 `Pods.xcodeproj` 放所有第三方庫，再用一個 <Term en="workspace" tw="工作區（.xcworkspace）" cn="工作空间" jp="ワークスペース" /> 把它跟你的 `.xcodeproj` 包在一起，並在你的 target 加上 `Pods-LittleBook.debug.xcconfig` 等設定檔，裡面寫了 `HEADER_SEARCH_PATHS`、`OTHER_LDFLAGS`。只開 `.xcodeproj` 的話，Xcode 看不到 `Pods.xcodeproj`，於是 `#import <Masonry/Masonry.h>` 變成 `file not found`，連結時一堆 `Undefined symbols`。11.6 的面試題會再問一次。

### use_frameworks!：靜態還是動態

```ruby
use_frameworks!                   # 每個 pod 建成動態 framework
use_frameworks! :linkage => :static   # 建成靜態 framework（CocoaPods 1.9+）
# 不寫：靜態函式庫（.a），所有 ObjC 符號連進主執行檔
```

純 ObjC 專案**不需要** `use_frameworks!`；本課程的 Podfile 也不加。Swift pod 以前必須用動態 framework，CocoaPods 1.9 之後靜態也行。<Term en="static / dynamic library" tw="靜態 / 動態函式庫" cn="静态 / 动态库" jp="静的 / 動的ライブラリ" />的取捨：動態 framework 多，App 啟動時 dyld 要逐個載入，超過幾十個就看得到啟動變慢；靜態連結啟動快但 `-ObjC` 旗標與 category 問題（11.6）就是這裡來的。

### 老牌庫怎麼讀

接手 2012–2018 的專案，Podfile 裡幾乎一定有這幾個。你不需要會寫，但要讀得懂它們的「風格」：

**AFNetworking**（網路）：`AFHTTPSessionManager` 單例 + success / failure 兩個 block。現代替代是直接用 `NSURLSession`（7.x），或 Alamofire（Swift）。

```objc
[[AFHTTPSessionManager manager] GET:@"https://api.example.com/rates"
    parameters:@{ @"base": @"TWD" } headers:nil progress:nil
    success:^(NSURLSessionDataTask *task, id json) { /* 已解析成 NSDictionary */ }
    failure:^(NSURLSessionDataTask *task, NSError *error) { }];
```

**Masonry**（Auto Layout）：<Term en="chainable DSL" tw="鏈式 DSL" cn="链式 DSL" jp="メソッドチェーン DSL" />，每個「屬性」其實是回傳 block 的方法，所以寫成 `.left.equalTo(view).offset(16)`。這是本章 Xcode 任務要重寫的：

```objc
// 8.2 的原生寫法
[NSLayoutConstraint activateConstraints:@[
    [self.amountField.leadingAnchor constraintEqualToAnchor:guide.leadingAnchor constant:16],
    [self.amountField.trailingAnchor constraintEqualToAnchor:guide.trailingAnchor constant:-16],
    [self.amountField.topAnchor constraintEqualToAnchor:guide.topAnchor constant:12],
    [self.amountField.heightAnchor constraintEqualToConstant:44],
]];

// Masonry 寫法：同一組約束
[self.amountField mas_makeConstraints:^(MASConstraintMaker *make) {
    make.left.right.equalTo(self.view.mas_safeAreaLayoutGuide).insets(UIEdgeInsetsMake(0, 16, 0, 16));
    make.top.equalTo(self.view.mas_safeAreaLayoutGuideTop).offset(12);
    make.height.mas_equalTo(44);
}];
// mas_updateConstraints: 更新既有約束；mas_remakeConstraints: 全部拆掉重建
```

讀法：`make.<屬性鏈>.<關係>(目標).<修飾>`。`equalTo()` 的參數可以是 view（取同名屬性）、`NSNumber`（常數）、或 `view.mas_left` 這類具名 attribute。`mas_equalTo()` 是巨集，會把 C 數值自動包成 `NSValue`。SnapKit 是它的 Swift 版，讀法完全一樣。

**SDWebImage**（圖片快取）：`UIImageView` 的 category，一行載圖、自動快取、自動取消重用 cell 的舊請求。`[imageView sd_setImageWithURL:url placeholderImage:ph];`

**MJRefresh**（下拉更新）：`UIScrollView` 的 category。`tableView.mj_header = [MJRefreshNormalHeader headerWithRefreshingBlock:^{ ... }];`，結束時 `[tableView.mj_header endRefreshing]`。

**FMDB**（SQLite 包裝）：`FMDatabaseQueue` 保證串列存取；`[queue inDatabase:^(FMDatabase *db) { [db executeUpdate:@"INSERT ..." withArgumentsInArray:args]; }]`。對照 9.x 的 JSON 持久化。

**YYKit / YYModel**（JSON ↔ 物件）：靠 runtime 讀屬性名自動對應，`[LBTransaction yy_modelWithJSON:json]`；自訂對應靠實作 `+modelCustomPropertyMapper`。對照 9.4 手寫的 `initWithDictionary:error:`——YYModel 快但出錯時無聲，手寫慢但能做防禦。

### Swift 專案用 ObjC pod、SPM 的 ObjC 支援

Swift target 加了 `use_frameworks!` 之後，每個 pod 變成一個 Clang module，CocoaPods 會自動產生 <Term en="module map" tw="模組對應檔" cn="模块映射" jp="モジュールマップ" />（`module.modulemap`），Swift 端直接 `import Masonry`。沒有 `use_frameworks!` 時要走 bridging header：`#import <Masonry/Masonry.h>` 寫進 `LittleBook-Bridging-Header.h`（12.x）。

Swift Package Manager 從 5.3 起支援 ObjC target：`Package.swift` 裡一個 target 的 `Sources/<name>/include/` 放公開標頭，SPM 自動生 module map。限制：一個 target 不能混 Swift 與 ObjC 檔（要拆兩個 target）、沒有 `-ObjC` 旗標的概念（靜態連結時 category 問題一樣存在，要靠 `-force_load` 或 `unsafeFlags`）。新專案如果只有 Swift，SPM 就夠；接手的 ObjC 專案多半短期內留在 CocoaPods。

<Tip title="Pods/ 進不進版控，先看 CI">
如果 CI 每次 clone 後跑 `pod install`，`Pods/` 不進版控 repo 小；如果 CI 直接 `xcodebuild`，`Pods/` 必須進。兩種都對，**換掉既有決定要全隊同意**：有人進有人不進，`.xcworkspace` 的參考會壞，出現 `The sandbox is not in sync with the Podfile.lock`。
</Tip>

## 小結

- `Podfile` 宣告、`Podfile.lock` 鎖定（**一定進版控**）、`Pods/` 安裝；三件組對應 Gradle、npm 的同一套概念。
- `pod install` 照 lock 裝（clone 後、CI、加減 pod）；`pod update` 刻意升級；開 `.xcworkspace` 不開 `.xcodeproj`。
- 純 ObjC 不用 `use_frameworks!`；動態 framework 多會拖慢啟動，靜態連結要留意 `-ObjC`（11.6）。
- 老牌庫的風格：AFNetworking 的 success / failure block、Masonry 的鏈式 DSL（`make.left.equalTo(view).offset(16)`）、SDWebImage / MJRefresh 的 category 擴充、FMDB 的 queue、YYModel 的 runtime 對應。
- Swift 用 ObjC pod 靠 module map 或 bridging header；SPM 支援純 ObjC target 但不能混語言、沒有 `-ObjC` 概念。
